## 0. Цель

После cutover контур B в новой структуре ведёт FEMSQ. Access на этих шагах ограничен самой схемой, а не запретом политики. Переходный период длинный: какой инструмент открыть на конкретном шаге, решает оператор. Другие модули FishEye, для которых в FEMSQ ещё нет замены, Access по-прежнему ведёт.

---

## 1. Матрица «кто пишет»

Легенда: **F** = FEMSQ · **A** = Access · **—** = не используется / запрет · **R** = только чтение.

| Объект / шаг БП | До cutover (сейчас) | Сразу после H | После dual-read off (I) |
|-----------------|---------------------|---------------|-------------------------|
| Общий свод → воронка C / `DbtValue` | F (DEV) / A пишет старый `cn_inv_dbt` | Оператор. A не пишет `invDbt` / `Dbt` / `DbtValue` | **F** |
| `export_*` → `cn_inv_pm` | F (DEV) / A INSERT в `ags.cn_inv_pm` | Оператор. A по-прежнему пишет `cn_inv_pm`; `g_p` и `DbtUplCstAg` не заполняет | **F** |
| Rslt сбор / повтор, возврат в `yr_CmmGr_New` | F | Оператор. Колонки New в Access нет | **F** |
| Правка cmm | F + A по `*InvAccnt` | Оператор. A не ведёт якорь `*Dbt` и текст `*Dv` | **F** |
| D644 · Выгрузить / Свод · Выгрузить | F (S59 DEV) / старый отчёт A | Оператор. Отчёт A не читает новую витрину | **F** |
| Краткий отчёт и `ags.fioDict` | Excel / VBA | Оператор. Продукт контура — FEMSQ | **F** |
| Модули вне контура B | A | A, пока в FEMSQ нет замены | A, пока нет замены |

**Не путать:** исходящий годовой **Свод · Выгрузить** (БП 1.2.1) ≠ краткий отчёт по входящему своду (БП 1.1.1.0).

---

## 2. Правила на переходный период

1. **Инструмент шага выбирает оператор.** Политика не запрещает Access и не назначает единственного писателя заранее.
2. **Один писатель на один и тот же срез.** Если шаг квартала уже записан одним инструментом, второй его не перезаписывает. Откат — решением оператора.
3. Запись в новый слой (`invDbt` / `Dbt` / `DbtValue`, `*Dbt`, `*Dv`, `yr_CmmGr_New`, `g_p` → `DbtUplCstAg`) делает FEMSQ: форм Access для этого слоя нет.
4. Файлы на шаре FEMSQ кладёт рядом с входом. Файл Access с тем же именем помечается `_access_`, чтобы не подменить результат FEMSQ.

## 3. Решение R3 (заполнить до окна H)

| Поле | Значение |
|------|----------|
| Дата решения | 2026-10-21 |
| Режим Access write после H | Запрета нет. Выбор Access или FEMSQ на шаге — у оператора на весь переходный период |
| Подпись владельца | Александр, в этом чате |
| Исключения | Модули вне контура B, для которых в FEMSQ нет замены, остаются в Access |

Проверка структуры в тот же день. Из шагов контура B Access по-прежнему вставляет строки в `ags.cn_inv_pm` (и связанные `cn_inv_doc` / `cnInvAccntSmpl`). Свод после шага карточки FEMSQ пишет в `invDbt` / `Dbt` / `DbtValue`; у Access остаётся старый `cn_inv_dbt`. Колонки `yr_CmmGr_New` в контуре Access нет. Комментарии Access идут по `*InvAccnt`, не по `*Dbt` / `*Dv`. Отчёт D644 Access не читает витрину `DbtValue`. Словарь `ags.fioDict` и краткий отчёт — продукт FEMSQ. Загрузка платежей не заполняет `g_p` и `DbtUplCstAg`.

Статус **R3** в [cutover](db-upgrade-sudz-invdbt-cutover.md) отмечен этой датой.
