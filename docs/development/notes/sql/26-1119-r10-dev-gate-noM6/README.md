# R1.0 DEV-гейт: схема «как прод без M6» без полного `.bak` прода

**Дата:** 2026-11-19  
**План:** [chat-plan-26-1117-release-r1x.md](../../chats/chat-plan/chat-plan-26-1117-release-r1x.md) §2.1  
**Задача:** 0086  

## Решение

Полный BACKUP прода **недоступен**. Для гейта R1.0:

1. **Прод (readonly):** оператор гоняет `MSSQL2012/00`–`02` в SSMS → сетки в Cursor (подтверждение «M6 нет», состав `sudz`, контур ревизий 0054).
2. **DEV:** клон локального `FishEye` → **`FishEye_prod_noM6`**, затем **strip** схемы `sudz` (слой M6/cutover). Рабочий `FishEye` не трогаем.

Ограничение: данные и прочий DDL на DEV могут отличаться от прода; цель гейта — **старт текущего JAR и ревизии 3/5/6 при отсутствии объектов M6**, как на проде (риск дорожной карты R1.0).

## Файлы

| Файл | Где | Назначение |
|------|-----|------------|
| `MSSQL2012/00_SURVEY_M6_readonly.sql` | прод (и verify DEV) | маркеры M6 / объёмы (наследник 26-1021) |
| `MSSQL2012/01_SUDZ_SCHEMA_inventory_readonly.sql` | прод | полный список объектов схемы `sudz` |
| `MSSQL2012/02_REVISIONS_inventory_readonly.sql` | прод | контур ревизий (0054) |
| `10_CLONE_to_FishEye_prod_noM6.sql` | DEV Docker 2022 | BACKUP/RESTORE в новую БД |
| `11_STRIP_sudz_schema.sql` | только `FishEye_prod_noM6` | удаление всех объектов `sudz` |
| `12_VERIFY_noM6.sql` | DEV после strip | PASS/FAIL маркеров |

## Чеклист оператору (прод)

**Сессия продОбмен:** `~/Downloads/продОбмен/26-1119_09-30/`  
**Архив в_Прод:** `26-1119_09-30_в_Прод_R10_DEV_GATE_SURVEY.zip` (AES-256, пароль обмена) + `.sha256`.

1. Отправить zip с канала продОбмен (как обычно).
2. SSMS → `SPB-05-NV-SQL1` / `FishEye`, Windows auth.
3. Выполнить `00` → `01` → `02` (только чтение); заполнить `RETURN_TEMPLATE.txt`.
4. Ответ → `отПрод/` этой же сессии → Cursor.
5. (Для 1.4, параллельно) файлы Excel ревизий af_type 3/5/6 с рабочего контура 156.

**Запрещено:** DDL/DML на прод; BACKUP не требуется.

## Чеклист DEV (после согласия на клон)

1. Свободное место на томе Docker: ориентир ≥ размер `FishEye` data+log (~3 ГБ + log; см. `sys.master_files`).
2. Выполнить `10_CLONE_…` от `sa` на `10.7.0.3` (или с nb-win через `docker exec sqlcmd`).
3. В контексте **`FishEye_prod_noM6`**: `11_STRIP_…`, затем `12_VERIFY_…`.
4. Сверить `12` с сетками прода по `00`/`01`.
