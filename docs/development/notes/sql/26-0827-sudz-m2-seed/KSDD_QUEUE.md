# КСДД — политика очереди (как КСДСФ)

**Дата:** 2026-08-28 · **22f** (excel resolve, 2026-08-30)  
**Сегм. 22b** (rebuild) · **22e** (Link/Create → `created`, 2026-08-29)

## Именование

**КСДД** — компонент сличения двоящих долгов (аналог **КСДСФ** для номеров СФ).

Таблица: `sudz.CnInvUplInvDbtDouble` · экран: `SudzInvDbtDoubleView`.

## Политика (согласовано с S68 / КСДСФ)

| Событие | Поведение |
|---------|-----------|
| **rebuild** (`invDbtLoad`) | `DELETE` **все** строки по `ciudUnloadKey`; `INSERT` только позиции Excel, требующие ручного разбора (`open`) |
| **Link / Create** на экране | `DbtValue` на upl + **`UPDATE ciudStatus = 'created'`**, `ciudCreatedIdKey` = слот |
| **Create var** / **Выбрать контекст** | строка остаётся `open`, обновляется `ciudIdvvKey` |
| **reason** | `multi` — несколько долгов/контекстов; `excel_unresolved` — текст Excel не дал ровно одного cnNum/invNum |
| **calm-excel** (22f) | однозначный Excel → ensure var + load без очереди; ложный `ambiguous` из ags.cnNum устранён |
| **Экран КСДД** | все статусы в гриде; кнопки только для `open` |
| **Launcher / бейдж «к разбору»** | счётчик только **`open`** |
| SoT «сделано» | **`DbtValue`** на текущем upl (сегм. 21); очередь — журнал разбора до rebuild |

## Для оператора

- Пустая вкладка **КСДД** на лаунчере = нет строк **`open`** (как КСДСФ).
- После успешного Link/Create строка остаётся в списке со статусом **`created`** (read-only) до следующего прогона загрузки/свода.
- Следующий **rebuild** пересчитывает open из Excel; «закрытые» Excel-строки не возвращаются, если на upl уже есть Value.
