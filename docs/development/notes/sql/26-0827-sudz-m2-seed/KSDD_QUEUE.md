# КСДД — политика очереди (как КСДСФ)

**Дата:** 2026-08-28  
**Сегм. 22b**

## Именование

**КСДД** — компонент сличения двоящих долгов (аналог **КСДСФ** для номеров СФ).

Таблица: `sudz.CnInvUplInvDbtDouble` · экран: `SudzInvDbtDoubleView`.

## Политика (согласовано 2026-08-28)

| Событие | Поведение |
|---------|-----------|
| **rebuild** (`invDbtLoad`) | `DELETE` **все** строки по `ciudUnloadKey`; `INSERT` только позиции Excel, требующие ручного разбора (`open`) |
| **Link / Create** на экране | `DbtValue` на upl + **DELETE** строки очереди (не `created` в таблице) |
| **Create var** | строка остаётся `open`, обновляется `ciudIdvvKey` |
| **Launcher / КСДД UI** | только `ciudStatus = 'open'` |
| SoT «сделано» | **`DbtValue`** на текущем upl (сегм. 21), не статус в очереди |

## Для оператора

- Пустая вкладка **КСДД** = нечего разбирать (как пустая очередь КСДСФ после rebuild).
- После успешного Link/Create строка **исчезает** из списка.
- Следующий прогон воронки пересчитывает open из Excel; «закрытые» Excel-строки не возвращаются, если на upl уже есть Value.

## Отличие от старой A2 v1

Раньше: DELETE только `open`, `created`/`deferred` жили между прогонами → путаница (тестовые `created`).

## UAT

После rebuild upl 910: в очереди только `open`; legacy `created` (1800, 2446) удалены rebuild-ом.
