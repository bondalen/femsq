## 1a. Экран A0 — «Портфель года» (`yr`)

**Цель:** вести год-вариант: база выгрузки, группа комментариев, перечень выгрузок года и связи с выгрузками платежей; просмотр хода (`yr_Progress`); **запуск** промежуточных и исходящих документов.

**Данные (префикс схемы = `sudz` на DEV / `ags` на prod — один код):**  
`yr`, `yr_upl_p`, `cn_inv_dbt_upl`, `cn_inv_dbt_upl_g_p`, `cn_inv_pm_upl`, `cnInvCmmGr`; `yyyy` — всегда `ags.yyyy`.

**CRUD:** да (новые годы и выгрузки заводятся здесь). `yr_Progress` — **read-only** (лог; append при формировании — по желанию реализации).

### Wireframe

```text
┌─ TopBar: … │ СУДЗ ▾ │ … ─────────────────────────────────────────────┐
├─ Портфель года                                      [+ Год] [Обновить]┤
│ ┌─ ~15% ──────────┬─ карточка выбранного yr ───────────────────────┐ │
│ │ yr_variant      │ Поля yr (+ lookup):                            │ │
│ │ [2026 осн.] ◄── │  variant | база | yyyy | CmmGr |[Сохр.]            │
│ │ [2025 осн.]     │────────────────────────────────────────────────│ │
│ │ …               │ Вкладки: [ Выгрузки ] [ Ход (Progress) ]       │ │
│ │                 │ Выгрузки (yr_upl_p), expand как агенты cst:    │ │
│ │                 │  ▸ upl_name | upl_date | uplStatusOnDate       │ │
│ │                 │     └ pm: cn_inv_pm_name | cn_inv_pm_date      │ │
│ │                 │ Progress: лаунчер документов + лог + прототип  │ │
│ └─────────────────┴────────────────────────────────────────────────┘ │
```

### Колонки / lookup (S51)

| Место | Поля |
|-------|------|
| Слева | только `yr_variant` |
| Шапка yr | `cn_inv_dbt_upl` → `upl_name`+`upl_date`; `yyyy` → `ags.yyyy`; `yr_CmmGr` → `cnicgName`+`cnicgDate` (`yr_CmmGr_New` — только Progress) |
| `yr_upl_p` | `upl_name` + `upl_date` + `uplStatusOnDate` |
| Раскрытие `g_p` | `cn_inv_pm_name` + дата; lookup и по `cn_inv_dbt_upl`, и по `cn_inv_pm_upl` |

### Вкладка «Ход (Progress)» — лаунчер операций (S52 / S58)

Контекст: выбранный **`yr`**. Выбор и CRUD **`yr_CmmGr_New`** — **только** на Progress при «· Загрузить» (в шапке года поля New нет).

```text
Операция: [ Rslt сбор · Выгрузить | Rslt повтор · Выгрузить | Rslt повтор · Загрузить | D644 · Выгрузить | Свод · Выгрузить ]
Срез:     [ из yr_upl_p ▾ ]              ← для · Выгрузить (Rslt: asOfUpl; D644/Свод: currUpl)
Группа новых: [ 904 · имя · дата ]       ← только «Rslt повтор · Выгрузить» (read-only)
Результат:(•) предпросмотр  ( ) Excel   ← только выгрузка Rslt
Папка:    [ test ] [📁]                  ← Excel (Rslt / D644 / Свод)

── если «Rslt повтор · Загрузить» ──
Группа новых (yr_CmmGr_New): [ 904 ▾ | + Создать ]
Файл возврата:               [ …xlsx ] [📎]

[ Выполнить ]
── подвкладки: Лог (yr_Progress) | Предпросмотр ──
```

**Предпросмотр Rslt:** native HTML-таблица в scroll-рамке (не FemsqTable — wide grid / sticky / cell-click); те же колонки, что в Excel; у сбора `*_new` пустые; **многострочные** заголовки (до 3 строк) + **поколоночные** фильтры (AND с глобальным); ячейки в одну строку, полный текст — в нижней панели; sticky шапка+фильтры при вертикальном скролле; кнопка «Выгрузить в Excel».

| Операция | Срез | Результат/папка | CmmGr_New + файл |
|----------|------|-----------------|------------------|
| **Rslt сбор · Выгрузить** | asOfUpl | да (proto/Excel) | нет (`*_new` пустые) |
| **Rslt повтор · Выгрузить** | asOfUpl | да (proto/Excel) | **read-only** (откуда `*_new`) |
| **Rslt повтор · Загрузить** | — | — | **да** → upsert в `yr_CmmGr_New` |
| **D644 · Выгрузить** | currUpl | да (proto/Excel) | нет (`yr_CmmGr`) |
| **Свод · Выгрузить** | currUpl | да (proto/Excel) | нет (`yr_CmmGr`) |

**S52a:** все выходные, кроме Rslt повтор · Выгрузить, читают только **`yr_CmmGr`**. Загрузка возврата всегда пишет в **`yr_CmmGr_New`** года (не комбо «подгрупп Access»).  
Процесс: [03 §1.1.2–1.1.3](../domain/sudz/03-processes.md).

**Шапка письма** — только для Excel D644/свода.

**Порядок реализации (0070):** (1) Rslt сбор → (2) Rslt повтор (+ DDL New) → (3) **D644/свод** ✅ S59; импорт возврата — Progress · Загрузить (S58).

**Папка Excel:** File System Access API (имя папки; **полный путь — отложен до отдельного решения**, S60). После операции — запись в `yr_Progress` (**новые строки сверху**, хранится до **~100** строк; старые отбрасываются).

**Excel Rslt:** стили эталона 26-0212 (S55); подпись idNum — «№ задолженности в СФ» (S56).
### Таблицы UI

**Списки** (годы, долги, стройки) — **FeQuLib** (`FemsqTable`). **Предпросмотр Rslt** — native grid (FeQuLib пока без sticky/wide-scroll/cell-click/multiline header). Раскрытие выгрузок — паттерн как дерево агентов на экране Строек.

## 2. Экран A — «Долги / мероприятия» (бывш. Rslt)

**Цель:** показать долги годового портфеля нарастающим итогом по срезам; дать ввод/правку куратора, мероприятий, кода стройки (**1.1.2.***; до вехи **1.1.3** — в группу `yr_CmmGr_New`, после вехи / для «официальных» — `yr_CmmGr`).

**Данные:** GraphQL → `sudz.Yr_DbtChanges`; запись → `sudz.cnInvCmm*` / целевая группа по этапу (`yr_CmmGr_New` на сборе, `yr_CmmGr` после вехи — уточнить при коде).

### Wireframe

```text
┌─ TopBar: … │ СУДЗ ▾ │ … ─────────────────────────────────────────────┐
├─ Заголовок: Долги / мероприятия · yr 901            [Обновить] [⋯] ─┤
│  Год: [2026 ▾]   База: 31.12.2025 (upl 901)   Актуал. группа: II.26 │
│  Фильтр: [счёт ГК ▾] [поиск контрагент/договор/СФ…        ] [Сброс] │
├─────────────────────────────┬───────────────────────────────────────┤
│ Список долгов (FemsqTable)  │ Карточка долга                        │
│ dbtKey│СГК│Контрагент│Overd│ │ 82 · 606012 · Газстройпром, АО        │
│  basе │док│стройка     │…  │ │──────────────────────────────────────│
│  82   │… │7947│70.5M │◄──│ │ Реквизиты (base / curr по вкладкам)    │
│  85   │… │А19 │9.5k  │   │ │  Договор · дата · ИНН · срок · суммы   │
│  …    │  │   │       │   │ │  СФ по срезам: А19 → 90 (только чтение)│
│                         ▲   │ │──────────────────────────────────────│
│                         │   │ │ Сбор на дату отчёта                  │
│                         │   │ │  Куратор / Мероприятия / Код стройки │
│                         │   │ │  [Сохранить]                         │
│                         │   │ │ Срезы + превью D644                  │
└─────────────────────────┴───────────────────────────────────────┘
```

### Поведение

1. Выбор года → загрузка витрины; master — одна строка на `dbtKey`.
2. Выбор строки → detail: реквизиты base/curr, история СФ по `upl_date`, поля сбора.
3. **Сохранить** пишет type=1/8 и cst в целевую группу этапа (на цикле сбора — **`yr_CmmGr_New`**; после вехи 1.1.3 / вне сбора — **`yr_CmmGr`**). Excel-колонки `*_new` — слой отчёта, не отдельная таблица.
4. Пустой портфель / ошибка GraphQL — empty/error как на экране организаций.
5. Колонки списка: минимум СГК, контрагент, base Overd, документ (base `invNumEnum`), код стройки года, куратор.

### Вне MVP экрана A

- Полный паритет всех колонок Access Rslt в одной таблице (достаточно detail + ключевые колонки списка).
- Согласование разделов (E5).

## 3. Экран B — «Исходящие документы»

**Цель (исторический эскиз G4):** превью и выгрузка D644 / свода.

**S52:** ядро перенесено на **A0 → Progress**. Экран B на MVP **не обязателен**; при появлении — тонкая обёртка тех же параметров (`yr`, срез, тип) без дублирования бизнес-логики.

### Wireframe (если оставляем пункт меню)

```text
┌─ TopBar: … │ СУДЗ ▾ │ … ─────────────────────────────────────────────┐
├─ Заголовок: Исходящие документы                     [Обновить]      ─┤
│  Год: [2026 ▾]   → переход/встраивание лаунчера Progress года       │
│  (те же тип / срез / прототип|Excel / Сформировать)                 │
└──────────────────────────────────────────────────────────────────────┘
```

### Поведение

1. Год + срез (`asOfUpl` / `curr_upl`) обязательны по типу документа.
2. Тип «Свод» доступен технически всегда; бизнес-смысл — после Q4 (подсказка в UI).
3. Превью = результат proc / отчётного слоя; выгрузка не меняет БД (кроме опционального append в `yr_Progress`).
4. Документ в D644 = base `invNumEnum` (решение S44).
