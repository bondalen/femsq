## 1. Глоссарий (кратко)

| Термин | Смысл |
|--------|--------|
| **Dbt** | Канон долга (постоянный id) |
| **invDbt** | Слот долга на СФ (`idInv` + `idNum`) |
| **invDbtDbt** | Связь слот ↔ канон |
| **invDbtVar** | Контекст: № дог., № СФ, счёт, сторона/дата |
| **DbtValue** | Суммы на слоте в конкретной выгрузке (upl) |
| **КСДД** | Очередь двоящих долгов воронки |

## 2. Найти долг (канон)

Экран **СУДЗ → Долг (канон)** (S78).

1. Фильтры — **в шапке колонок** таблицы сверху (не отдельная форма). Обычно начать с **№ СФ**; при необходимости добавить **№ договора**.
2. При десятках строк — сузить: исполнитель (**БУиРГ** / **Организация**), дата стороны (`ГГГГ-ММ-ДД`), **№ слота в СФ** (`idNum`).
3. Если известен **`dbtKey`** — ввести его: открытие однозначно.
4. Клик по строке открывает **карточку Dbt** (вкладки **Долг** / **Слоты** / **Комментарии**).

Четвёрка/пятёрка **не** всегда = один `Dbt` без `dbtKey` или выбора из списка.

## 3. Привязать / отвязать слот

На карточке канона, вкладка **Слоты**:

- **Привязать слот** — связать существующий `invDbt` с этим `Dbt` (таблица `invDbtDbt`).
- **Отвязать слот** — снять связь. Если на слоте есть `DbtValue`, система откажет, пока Value не сняты (кнопка «Снять Value» в дереве вкладки **Долг**).

Вкладка **Долг:** слева **дерево** (слот → var → DbtValue с именем/датой upl), справа **график**: на слот две области (просрочено снизу, текущее = `ttl−overd` сверху). Ось X — дата среза (`uplStatusOnDate`, иначе дата выгрузки), подписи **ГГ-ММ** (`25-12`); после последнего среза область продлевается на **месяц**. Клик по слоту в таблице или дереве приглушает чужие серии. Даты 2018 в таблице слотов — сторона договора (`csoDate`), не история Value.

«Разделить» / «Слить» — модалки **Split** / **Merge** на выбранном слоте дерева (GraphQL `splitSudzDbt` / `mergeSudzDbt`), не отдельные «волшебные» кнопки без атомов.

## 4. Ситуации (накопление)

### 4.1. Свод N×S = Value слота (как 85166)

Очередь **КСДД**, советник `split` → кнопка «Split на доли». Create/Link при split не использовать.

### 4.2. Произвольное N→M / иной итог между выгрузками

Вне системы решить состав долей → на экране канона: привязать/отвязать слоты → в дереве **Добавить / Править / Снять Value**; при необходимости **Split** (доли одной upl) или **Merge**. Не смешивать с экраном «Долги / мероприятия» (Rslt/cmm).

### 4.3. G2: нет стороны с датой Excel

Исправить договор/сторону (Договоры / 0071), повторить префикс воронки до G2 PASS.

### 4.4. G5: ambiguous var (два `cn_s_org`)

Оставить мост с датой, совпадающей со сводом; лишний sentinel не оставлять на слоте. Затем `dbtValueLoad` с корректным `yrKey` (PIT).

### 4.5. P3 / documented exceptions

См. `p3_data_gap_manifest.json`. 105449 отсутствует в QI — ожидаемо для C.10.5.

### 4.6. Комментарии на каноне

Вкладка **Комментарии:** слева **то же дерево**, что «Долг» (Dbt → слот → DbtValue), справа текст. Лист комментария висит на **Value**, не на `yr_CmmGr` как корне.

Добавить: выделить **DbtValue** → «Добавить комментарий» → в модалке **группа** (`yr_CmmGr` / `yr_CmmGr_New`) и тип (мероприятия / куратор).

Пока **типы 1/8**. Save/Reset пишут GraphQL `upsertSudzDbtCanonComment` (`cnicDv`). Delete — с подтверждением. Пустой Save **не** удаляет строку. Экран «Долги / мероприятия» не дублировать (там ещё `cnicInvAccnt`=dbtKey).

## 5. Чего система не делает сама

Не выбирает один `Dbt` при нескольких кандидатах с одной СФ.  
Не считает неоднозначность «ошибкой данных» без решения оператора.  
Full apply воронки без gate'ов — запрещён (см. runbook).
