## Ключевые выводы из описаний (для модели)

- **`cnInvAccnt`** в описании названа **«Табличка, собственно, задолженностей»** и прямо фиксирует эволюцию идентификации: тройка договор–СФ–СГК → четвёрка +контрагент → всё ещё мало → нужно **имя** (пример двух задолженностей на одном счёте/контрагенте). Это стыкуется с S5 и костылём `ciaName`.
- **`cn_inv_dbt.cidCnInvAccntCtpt`** и **`cn_inv_pm.cidCnInvAccntCtpt`** описаны как **«Ключ собственно задолженности»** → операционный указатель на `cnInvAccnt`.
- Кластер **`cnInvCmm*`**: поля `*InvAccnt` описаны как **«ключ задолженности»** (20.12.2021).
- **`invDbt`** — «задолженности по счёту-фактуре»; **`invDbtValue`** — «величина задолженности в выгрузках» (недоделанный слой рядом).
- **`cn_inv_dbt`** — ДЗ **именно в этой выгрузке** по документу основания (СФ); **`cn_inv_dbt_upl`** — отчёт кв. «Выгрузка Бухгалтерии Ф644».
- **`cn_inv_pm_upl` / `cn_inv_pm`** — «Расширенная выгрузка» и платежи/остатки по ней (контур `export_*` / PM).
- **`cnInv`** — «Счета фактуры. Вариант второй…»; **`inv`** — «Основная таблица счётов-фактур» (04.01.2022).

### `cnInvAccnt`

Табличка, собственно, задолженностей. По состоянию на 07.12.2021 наступило понимание, что задолженность не идентифицируется тройкой договор-СФ-СГК, нужно расширить до четвёрки договор-СФ-СГК-контрагент (с датой). И даже этим не идентифицируется. Ещё нужно имя, так как существует 0818 CR 0096/АА01/, имеющий две задолженности в одной выгрузке для одного счёта и контрагента

### `cnInvAccntSmpl`

Факты связи тройки:

1. пара *Счёт-фактура + Договор*,
2. счёт главной книги,

## Описания полей

### `cn_inv_dbt`

- **`cn_inv_dbt_upl`** — Ключ выгрузки.
- **`cidCnInvAccntCtpt`** — Ключ собственно задолженности. Добавлен 07.12.2021
- **`cidTimeOfEntry`** — 19.01.2022 Дата и время внесения

### `cn_inv_pm`

- **`cn_inv_key`** — Сейчас, на 18.05.2021, полем для связи со счётом-фактурой является поле cipCnInvAccnt (учитывающее номер счёта главной книги). Настоящее поле сохраняется на всякий случай
- **`cn_s_agent`** — Это поле для хранения Агента из выгрузки платежей. 21-1202 сделал его не обязательным. Допускающим Null. Это по тому что с догрузкой данных по дополнительным счетам пришлось бы делать много не существующих заказчиков по договорам.
- **`cn_inv_pm_due`** — Срок оплаты
- **`dbt_blns`** — СальдоКонечноеДт
- **`dbt_blns_overd`** — СальдоКонДтПросроченное
- **`dbt_blns_not_overd`** — СальдоКонДтНепросроченн
- **`cdt_blns`** — СальдоКонечноеПоКт
- **`cdt_blns_overd`** — СальдоКонКтПросроченное
- **`cdt_blns_not_overd`** — СальдоКонКтНепросроченн
- **`blns`** — СальдоКонечное
- **`alignment_date`** — Д/выравн.
- **`base_date`** — БазДата
- **`storno_reason`** — ПричСторн
- **`storno_doc`** — ДокСторно
- **`cn_inv_doc_date`** — Д/документ
- **`cn_inv_doc_date_entry`** — Д/проводки
- **`cn_inv_doc_sum`** — СуммаДокумента
- **`cn_inv_doc_link`** — Ссылка
- **`cnInvKey`** — Сейчас, на 18.05.2021, полем для связи со счётом-фактурой является поле cipCnInvAccnt (учитывающее номер счёта главной книги). Настоящее поле сохраняется на всякий случай
- **`cipCnInvAccnt`** — На 18.05.2012 это поле для связи со счётом-фактурой. cn_inv_key и cnInvKey сохраняются пока на всякий случай.
- **`cidCnInvAccntCtpt`** — Ключ собственно задолженности. Добавлен 07.12.2021
- **`csoCn_s_org_smpl`** — ключ организации-простой стороны договора. Добавлен 21-1208. Это агент

### `cn_s_org`

- **`csoAsbuID`** — Идентификатор договора для организации (стороны) в АСБУ
- **`csoCnDate`** — Дата договора для отдельной организации (стороны). Соответствует полю "Дата догов" справочника договоров АСБУ

- **`cstapIpgPnN`** — Код объекта *Стройка-Агент-Код*
- **`cstapCstName`** — Получаем строчное наименование стройки по ключу объекта "стройка-агент-код"
- **`cstapCstName255`** — Получаем строчное наименование стройки по ключу объекта "стройка-агент-код" длиною не более 255 символов
- **`cstapOgName`** — Получаем строчное наименование организации по ключу объекта "стройка-агент-код"

### `invDbt`

- **`idInv`** — счёт-фактура
- **`idNum`** — номер задолженности в пределах счёта-фактуры
- **`idNote`** — краткое описание задолженности

### `invDbtValue`

- **`idvDbtInv`** — идентификатор счёта-фактуры, часть внешнего ключа из таблицы задолженностей счёта-фактуры
- **`idvDbtInvNum`** — номер счёта-фактуры, с которым в данной выгрузке фигурировала задолженность
- **`idvDbtNum`** — номер задолженности, часть внешнего ключа из таблицы задолженностей счёта-фактуры
- **`idvUpl`** — выгрузка задолженностей
- **`idvAccnt`** — Счет Главной книги
- **`idvCnPartyOrg`** — наверное, это лишнее
- **`idvOrgName`** — контрагент, наименование
- **`idvOrgNum`** — контрагент, номер БУиРГ (№ контрагента)
- **`idvOrgTin`** — контрагент, ИНН

### `invNum`

- **`inNumNull`** — При отсутствии значения (Null) в поле номера счёта-фактуры, либо при значении, равном пустой строке (''), приводим номер договора к виду 'NullИлиПусто'
