## 1. Назначение

**СУДЗ** (система управления дебиторской задолженностью) — домен учёта и сопровождения **просроченной дебиторской задолженности**, по которой ведётся работа в течение календарного года.

В Access это действующая подсистема (клиент к **FishEye.ags**); в FEMSQ — целевой аналог (документация и проектирование сейчас, реализация — после стабилизации модели).

---

## 2. Бизнес-рамка

### Цикл и объект

- Работа ведётся **ежеквартально**.
- Объект года Y — просроченные задолженности из свода на **31.12.(Y−1)** (**портфель начала года**).
- Задолженности, **ставшие просроченными в течение года Y**, в работу и в итоговые сведения **не** входят.
- Свод на **31.12.Y** задаёт портфель на год Y+1.

### Входы квартала

- **Общий свод ДЗ** из бухгалтерской системы: `Дт Задолженность на 3*.**.202* (Общий свод)*.xlsx`.
- Файлы **`export_{счётГК}_*`** — для привязки задолженности к стройке (`cst` / `cstAgPn`), которой нет в общем своде.

### Главная техническая проблема модели

Идентификация **одной и той же задолженности** между выгрузками свода:

- на эксплуатации: **`cnInvAccnt`** = задолженность, **`cn_inv_dbt`** = значение в выгрузке;
- при стабильном СФ работает (пример Rslt 82); при смене СФ — ручной match (Rslt 85) — [04-2](./04-2_example-rslt-82-85.md);
- реестр проблем (**P1** смена объекта документа суд↔СФ, **P2** несколько долгов на зонтике, **P5** переименование СФ, **P6/P7** стороны/Smpl/`export`): [04-3](./04-3_problems-solutions.md).

**Целевое усиление:** полноценный match к стабильному ID при смене СФ/`inv`. Подробно: [04-data-model §1.1](./04-data-model.md).

### Промежуточный оборот

- Выгрузка из **FishEye.ags** файла **`ags_Yr_DbtChangesRslt_2*-****.xlsx`** (сопоставленные задолженности нарастающим итогом) → специалисты → сбор мероприятий → обратно в БД.

### Выход квартала / года

- **Итоговый документ** (ежеквартально) — `Приложение N. Сведения о ходе работы по балансовым счетам 606012, 762210, 767502.xlsx` (лист `ags_Yr_DbtChangesRsltD644_*`) → заинтересованное подразделение.
- **Итоговый сводный документ** (раз в год, по итогам Q4) — `Приложение 1. Информация о состоянии дебиторской задолженности в разрезе счетов бухгалтерского учета.xlsx`; направляется **вместе** с итоговым за четвёртый квартал.
- Финальная сборка приложений — Access-запросы (в т.ч. семейство `*D644*`) поверх данных SQL Server; история SQL: `femsq/debit/23-0421_sql.docx`. Образцы и шаги: [03-processes §1.2](./03-processes.md).

Клиент ко всем операциям с БД на текущем этапе — **MS Access**.

## 3. Границы

**Входит (целевое):**

- загрузка квартальных сводов и `export_*` в `ags`;
- сопоставление / идентификация задолженностей и привязка к стройке;
- оборот `ags_Yr_DbtChangesRslt` со специалистами;
- учёт мероприятий по урегулированию;
- подготовка, согласование и выпуск **итогового** (и раз в год — **сводного**) документа для подразделения;

**Не входит / соседние контуры (пока не смешивать):**

- ревизии `ra_a` / reconcile Excel агентов;
- полный CRUD строек как домен (здесь `cst` / `cstAgPn` — **ключ привязки** долга, не предмет ведения стройки);
- полный контур договоров/счетов как CRM — только связь с задолженностью.
