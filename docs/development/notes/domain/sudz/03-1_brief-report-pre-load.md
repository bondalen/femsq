## 0. Назначение

Автоматизация FEMSQ — отдельно (контур B, узел **1.1.1.0.3**; целевой UX — §5).

## 2. Бизнес-порядок (два действия)

```text
получен свод (много листов по СГК)
  → Действие 1: перенос на один лист + итоги + формулы
  → Действие 2: ФИО → фамилия + инициалы (VBA fio + Справочник)
  → готовый краткий отчёт (2_ready)
  → (далее) загрузка свода в БД — БП 1.1.1.1
```

---

## 3. Действие 1 — перенос на один лист, итоги, формулы

### 3.1. Что делается

1. Данные со **всех листов-счетов** общего свода переносятся на **один** лист краткого отчёта.
2. Листы свода идут блоками **по счёту ГК**; после строк каждого счёта — строка **`ИТОГО по Счёту {СГК}:`**.
3. В конце листа — строка **`ВСЕГО дебиторская задолженность:`** (сумма итогов по счетам).
4. Для каждой **строки долга** добавляются вычисляемые поля (см. §3.3).

Порядок блоков счетов в образце `2_ready` (по строкам ИТОГО):  
`601300` → `601750` → `601760` → `606012` → `606022` → `682102` → `761010` → `762210` → `767401` → `767403` → `767501` → `767502`  
(в своде есть также лист `767402 нет` — в готовом отчёте отдельного блока нет).

Шапка отчёта (строки 1–4): приложение к письму; заголовок «Отчет по дебиторской задолженности»; дата отчёта («Отчет на "31" марта 2026 г.»).  
Строка 6 — заголовки колонок; в **`L6`** хранится **дата отчёта** как serial Excel (`46112` = **2026-03-31**) — опора для формулы дней просрочки.

### 3.2. Маппинг полей: свод (лист СГК) → краткий отчёт

Заголовки свода (строка 1 каждого листа-счёта) → колонки краткого отчёта (строка 6):

| Свод (лист СГК) | Краткий отчёт | Примечание |
|-----------------|---------------|------------|
| B `Счет Главной книги` | **A** `Счет Главной книги` | перенос |
| E `№ контрагента` | **B** `№ контрагента` | перенос |
| C `Контрагент` | **C** `Контрагент` | перенос; после действия 2 — с инициалами |
| F `Договор` | **D** `Договор` | перенос |
| H `Документ основания (счет-фактура)` | **E** `Реквизиты документа основания (счет-фактура, N и дата первичного документа и т.п.)` | перенос значения; **переименование** заголовка |
| I `Дата образования` | **F** `Дата образования` | перенос |
| J `Срок погашения` | **G** `Срок погашения` | перенос |
| K `Всего сумма задолженности в рублях` | **H** то же имя | перенос |
| L `Просроченная задолженность в рублях` | **I** то же имя | перенос |
| — | **J** `Количество дней просрочки` | **новое**, формула |
| — | **K** `Непросроченная задолженность в рублях` | **новое**, формула |
| — | **L** (только L6) | дата отчёта (serial), не колонка данных |

**Не переносятся** из свода в краткий отчёт:

| Свод | Почему |
|------|--------|
| A `Вид задолженности` | нет в отчёте |
| D `ИНН` | нет в отчёте |
| G `Дата договора` | нет в отчёте |
| M `Документ основания (присвоение ГК)` | нет в отчёте |
| N `Ссылка` | нет в отчёте |

### 3.3. Порядок заполнения строки долга

1. Скопировать с листа СГК поля по маппингу §3.2 в колонки **A–I** (значения; даты — как в своде).
2. Заполнить **J** (дни просрочки): формула вида **`=$L$6−G{строка}`** (дата отчёта минус срок погашения).  
   В готовом `2_ready` у части строк формула сохранена, у части — уже посчитанное значение (кэш/вставка значений).
3. Заполнить **K** (непросроченная): формула вида **`=H{строка}−I{строка}`** (всего − просроченная).  
   Аналогично: часть строк с формулой, часть — значение.
4. После последней строки счёта — строка итога: **A** = СГК, **C** = `ИТОГО по Счёту {СГК}:`, **H/I/K** = `SUM` по диапазону блока счёта.
5. После всех счетов — **ВСЕГО…**: **H/I/K** = сумма ячеек итогов по счетам.

## 4. Действие 2 — инициалы имени и отчества

### 4.1. Что делается

Во всех ячейках колонки **«Контрагент»**, где значение — ФИО физлица (**Фамилия Имя Отчество**), заменить **имя и отчество на инициалы**:  
`Калашникова Ольга Васильевна` → `Калашникова О.В.`  
Юрлица / учреждения (ООО, ПАО, АДМИНИСТРАЦИЯ, …) **не** сокращаются.

В образце: на листе **`все счета`** в `1_process.xlsm` ещё полные ФИО; в **`2_ready.xlsx`** — уже инициалы.

### 4.2. Лист `Справочник` (образцы имён и отчеств)

Именованный диапазон Excel: **`Словарь`** = `Справочник!$A$1:$F$211`.

Строки — карточки «базового» имени; колонки — варианты написания:

| Кол. | Роль (по содержимому образца) | Пример (`Александр`) |
|------|------------------------------|----------------------|
| **A** | имя (часто мужской вариант / основная форма) | Александр |
| **B** | парное / женское имя (где есть) | Александра |
| **C** | отчество муж. (основное) | Александрович |
| **D** | вариант отчества муж. | (редко; у «Анатолий» — Анатолиевич) |
| **E** | вариант отчества жен. | (напр. Артаваздовна) |
| **F** | отчество жен. (основное) | Александровна |

Непустых ячеек в образце: A=211, C=106, F=86, E=31, B=17, D=9.  
Заголовков на листе нет — данные с **A1**.

Назначение: словарь **слов** (имён и отчеств), по которым VBA отличает второе/третье слово ФИО от «не имени» и строит regex-замену.

### 4.3. VBA-модуль `fio` — функция `FioByDictionary`

Источник: модуль **`fio`** в `1_process.xlsm` (экспорт владельца, 2026-09-18). Это **UDF** (вызывается из ячейки Excel по строке текста), а не макрос, обходящий колонку целиком.

**Сигнатура:** `Function FioByDictionary(txt As String) As String`  
`Application.Volatile` — пересчёт при изменении книги.

**Алгоритм:**

1. `Range("Словарь")` — если нет → `"Ошибка: Диапазон 'Словарь' не найден"`.
2. Все непустые `Trim(cell.Value)` из диапазона → `Scripting.Dictionary` (уникальные слова).
3. Если словарь пуст → `"Ошибка: Словарь пуст"`.
4. `patternStr = Join(dict.Keys, "|")`.
5. `VBScript.RegExp`: `IgnoreCase = True`, `Global = False`,  
   `Pattern = "^([А-ЯЁа-яё-]+)\s+(" & patternStr & ")\s+(" & patternStr & ")$"`  
   — ровно три слова: фамилия + имя∈словаря + отчество∈словаря.
6. При match:  
   `Фамилия` + пробел + `UCase(Left(имя,1))` + `.` + `UCase(Left(отчество,1))` + `.`  
   → вид **`Фамилия И.О.`** (даже если в ячейке было «иван иванович»).
7. Если match нет:
   - число слов ≠ 3 → `"Отказ: слов не 3, а N"`;
   - иначе → `"Отказ: слов(а) отсутствуют в словаре"`.
8. Любая другая ошибка → `"Ошибка: " & Err.Description`.

**Код (эталон):**

```vb
Function FioByDictionary(txt As String) As String
    On Error GoTo ErrHandler
    Application.Volatile

    Dim regEx As Object, dict As Object
    Dim cell As Range, patternStr As String

    ' 1. Собираем уникальные слова
    Set dict = CreateObject("Scripting.Dictionary")

    Dim rng As Range
    On Error Resume Next
    Set rng = Range("Словарь")
    On Error GoTo ErrHandler

    If rng Is Nothing Then
        FioByDictionary = "Ошибка: Диапазон 'Словарь' не найден"
        Exit Function
    End If

    For Each cell In rng
        If Not IsError(cell.Value) Then
            If Trim(cell.Value) <> "" Then
                dict(Trim(cell.Value)) = True
            End If
        End If
    Next cell

    If dict.Count = 0 Then
        FioByDictionary = "Ошибка: Словарь пуст"
        Exit Function
    End If

    patternStr = Join(dict.Keys, "|")

    ' 2. Настройка Regex
    Set regEx = CreateObject("VBScript.RegExp")
    regEx.IgnoreCase = True
    regEx.Global = False
    regEx.Pattern = "^([А-ЯЁа-яё-]+)\s+(" & patternStr & ")\s+(" & patternStr & ")$"

    Dim cleanTxt As String
    cleanTxt = Trim(txt)

    If regEx.test(cleanTxt) Then
        Dim matches As Object
        Set matches = regEx.Execute(cleanTxt)
        FioByDictionary = matches(0).SubMatches(0) & " " & _
                          UCase(Left(matches(0).SubMatches(1), 1)) & "." & _
                          UCase(Left(matches(0).SubMatches(2), 1)) & "."
    Else
        Dim words() As String
        words = Split(cleanTxt, " ")

        If UBound(words) <> 2 Then
            FioByDictionary = "Отказ: слов не 3, а " & (UBound(words) + 1)
        ElseIf Not regEx.test(cleanTxt) Then
            FioByDictionary = "Отказ: слов(а) отсутствуют в словаре"
        End If
    End If
    Exit Function

ErrHandler:
    FioByDictionary = "Ошибка: " & Err.Description
End Function
```

**Применение на листе:** в колонке «Контрагент» (или вспомогательной) — формулы вида `=FioByDictionary(...)`; в `2_ready` результат уже **значениями** (инициалы без текстов отказа).

## 5. Целевой сценарий автоматизации в FEMSQ (продукт)

**Статус:** зафиксирован владельцем 2026-09-18; реализация — WBS **1.1.1.0.3** (не стартовать параллельно с активным каноном **b** / 0076 без явного решения).

### 5.1. UX оператора

1. Оператор открывает экран **подготовки краткого отчёта** (TopBar СУДЗ).
2. Указывает файл общего свода: выбор файла **или** путь в поле экрана (как лаунчер C/D; резолв пути — тот же контур шары/WSL).
3. Нажимает **«Подготовить»**.
4. Рядом с файлом свода создаётся Excel краткого отчёта с именем  
   `{имя_файла_свода_без_расширения}_краткий_отчёт.xlsx`  
   (пример: `Дт Задолженность на 31.03.2026 (Общий свод) -НОВЫЙ_краткий_отчёт.xlsx`).
5. В **логе** экрана — ход подготовки (блокеры, сводки по листам/счетам, отказы FIO, путь результата).

Содержимое файла — по бизнес-порядку §2–§4 (один лист, итоги, формулы J/K, инициалы через словарь БД).

### 5.2. Словарь на сервере

- Таблица **`ags.fioDict`** (бизнес-имя «Словарь») + представление **`ags.v_fioDictWord`** (DISTINCT слова для regex).
- Seed из листа `Справочник` / диапазона `Словарь` (`1_process.xlsm`) — пакет [26-0918-sudz-brief-report-fio-dict](../../sql/26-0918-sudz-brief-report-fio-dict/) (**✅ DEV**, 211 / 460).
- Логика инициалов — порт `FioByDictionary` (§4.3 / §6.6), источник слов — **`ags.v_fioDictWord`**, не именованный диапазон Excel.
- **Вторая вкладка** того же экрана: просмотр/правка строк словаря (CRUD), без Excel VBA.

### 5.3. Опоры в коде FEMSQ (не новый стек)

Путь к файлу — `SudzDbtUplExcelPathResolver`; Excel — POI; лог — HTML Progress; UI — паттерн экранов C/D; запись рядом со сводом — write-доступ JAR к каталогу шары (как read у `export_*`).

## 6. Спека backend **1.1.1.0.3.2** (алгоритм для реализации; код ☐)

Назначение: один прогон «путь свода → Excel краткого отчёта рядом» без UI (UI — `.3.3`). Эталон поведения — §3–§4 и файл `2_ready.xlsx`.

### 6.1. Контракт входа / выхода

| | |
|--|--|
| **Вход** | Абсолютный или резолвимый путь к файлу **общего свода** (`.xlsx`/`.xlsm`), как у лаунчера C/D |
| **Параметр даты отчёта** | По умолчанию — из имени/контекста QI или явная дата; для QI 2026_03 эталон **`2026-03-31`** → Excel serial **`46112`** в `L6` |
| **Словарь** | `SELECT word FROM ags.v_fioDictWord` (кэш на прогон) |
| **Выход** | Файл в **том же каталоге**, что свод: `{basename(свод)}_краткий_отчёт.xlsx` |
| **Побочный выход** | Поток событий лога (строки Progress/HTML), без отдельного файла |

Пример имени:  
`Дт Задолженность на 31.03.2026 (Общий свод) -НОВЫЙ_краткий_отчёт.xlsx`

Если целевой файл уже существует — **перезаписать** (или блокер с явным сообщением в логе; выбрать одно поведение при коде; для UAT — перезапись ОК).

### 6.2. Конвейер (порядок шагов)

```text
1. Resolve path → открыть свод (POI)
2. Detect sheets-счетов (§6.3) → упорядочить
3. Создать книгу результата: один лист (имя напр. «краткий» / как в эталоне — не критично для UAT сумм)
4. Шапка строк 1–4 + заголовки строки 6 + L6 = asOf (§6.4)
5. Для каждого СГК: строки долга A–I, J, K → строка ИТОГО (§6.4–6.5)
6. Строка ВСЕГО (§6.5)
7. Колонка C: порт FioByDictionary по кэшу слов (§6.6) — писать **значения**, не формулы UDF
8. Save рядом со сводом; финальная строка лога с путём
```

Действие 1 (перенос/итоги) и действие 2 (инициалы) в продукте — **один** backend-прогон; раздельность только бизнес-логическая.

### 6.3. Листы свода и порядок блоков

1. Перечислить листы книги свода.
2. Кандидат в блок СГК: имя листа **совпадает с 6-значным** кодом счёта **или** начинается с него (пробел/суффикс).  
   **Исключить** листы вроде `767402 нет` (нет отдельного блока в `2_ready`).
3. Порядок блоков — **как в эталоне QI** (не алфавит имени файла):

`601300` → `601750` → `601760` → `606012` → `606022` → `682102` → `761010` → `762210` → `767401` → `767403` → `767501` → `767502`

4. Если в своде есть **новый** 6-значный лист, отсутствующий в эталонном списке — **добавить в конец** (и написать в лог `WARN: unknown sheet {name}`); не падать.
5. Если эталонный СГК **отсутствует** в своде — пропуск блока + `WARN` в логе (не блокер, если так задумано оператором).

На каждом листе-счёте: строка 1 — заголовки; данные со **строки 2** до первой полностью пустой по ключевым колонкам (или до конца used range) — уточнить на реализации по POI `getLastRowNum`, отбрасывая пустые хвосты.

### 6.4. Шапка, маппинг строки долга, формулы J/K

**Шапка (как §3.1):**

| Строка | Содержимое (QI) |
|--------|-----------------|
| 1 | «Приложение № 1 к письму…» (в эталоне в зоне K; допустимо A/merge — UAT не сверяет вёрстку письма) |
| 3 | `Отчет по дебиторской задолженности` |
| 4 | `Отчет на "31" марта 2026 г.` (текст согласовать с asOf) |
| 6 | Заголовки A–K по §3.2 |
| **L6** | Дата asOf как **число** Excel (serial), не текст |

**Строка долга** — маппинг §3.2 (свод → A–I). Даты F/G — как date-ячейки POI (не ломать serial).

| Кол. | Правило |
|------|---------|
| **J** | `=$L$6−G{r}` (дни просрочки). В продукте допустимо писать **формулу** POI **или** вычисленное long/double; для UAT важна **численная близость** к `2_ready` (±0 при целых днях). |
| **K** | `=H{r}−I{r}`. Пустая/null просрочка **I** трактовать как 0 при вычислении K (в эталоне у части счетов I на ИТОГО пусто, K=H). |

Строки без суммы H (пустые/служебные) **не** копировать.

### 6.5. Итоги по счёту и ВСЕГО

После блока строк СГК — одна строка:

| Кол. | Значение |
|------|----------|
| **A** | код СГК |
| **C** | `ИТОГО по Счёту {СГК}:` (буква **ё** как в эталоне) |
| **H / I / K** | `SUM` по долгам блока (формула или значение) |

После всех блоков — строка:

| Кол. | Значение |
|------|----------|
| **C** | `ВСЕГО дебиторская задолженность:` |
| **H / I / K** | сумма соответствующих ячеек **всех** строк ИТОГО |

### 6.6. Порт `FioByDictionary` (словарь БД)

Вход: текст ячейки **C** после переноса (полное ФИО или юрлицо).  
Словарь: множество строк из `ags.v_fioDictWord` (Trim, непустые; регистр для regex — ignore case).

Алгоритм — §4.3 с заменой `Range("Словарь")` на кэш слов:

1. Пустой словарь → блокер прогона: `Ошибка: Словарь пуст` (не писать файл / или писать без инициалов — **предпочтительно блокер**).
2. Regex: `^([А-ЯЁа-яё-]+)\s+(word1|word2|…)\s+(word1|word2|…)$`, ignore case, не global.
3. Match → `Фамилия` + ` ` + `Upper(Left(имя,1))` + `.` + `Upper(Left(отчество,1))` + `.`
4. Нет match, слов ≠ 3 → оставить **исходный** текст C; в лог счётчик `fio_skip_wordcount` (не писать в ячейку строки «Отказ:…» — в `2_ready` отказов нет).
5. Нет match, слов = 3, но не в словаре → оставить исходный текст; счётчик `fio_skip_dict`.
6. Юрлица (не 3 словарных токена) остаются как есть.

**Не** эмитить в Excel тексты `"Отказ:…"` / `"Ошибка:…"` в колонку C (отличие от сырого UDF на листе процесса).

Кэш regex/pattern строить **один раз на прогон** (словарь до ~460 слов — ок).
