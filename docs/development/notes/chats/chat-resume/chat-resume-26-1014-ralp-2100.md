**Дата:** 2026-10-14 – 2026-10-15  
**Последнее обновление:** 2026-10-15  
**Тема:** Падение ревизии аренды земли на проде (`errorCode=8003`, больше 2100 параметров) и расхождение итога Excel «Принято затрат, руб.» с суммой, которую показывает приложение.

## Контекст

- Ревизия type=3, файл `(2026)_Аренда_рабочий.xlsx` из `/mnt/nb-win-share/femsq/excel/2026-1014/`.
- На проде `ags.ralpRa` за 2026 год: **2292** строки. Stage 1 успешен, сверка падала.
- На проде до фикса стоял thin **0.1.0.155**. Текущая линия main на момент чата — **0.1.0.347-SNAPSHOT**. Полный переход 155 → 347 на старый `lib/` не делался.

## Причина падения сверки

`RalpReconcileService.loadDomainRaAu` строил `WHERE ralpraRa IN (?×N)` на все ключи года. При 2292 ключах SQL Server 2012 отвечает `8003`: максимум **2100** параметров на запрос. Урезание Excel это не снимает: параметр шлёт JAR.

## Исправление

Только `femsq-web`, без DDL:

1. `loadDomainRaAu` — `JOIN ags.ralpRa` по `ralprY = ?` (один параметр).
2. `deleteByKeys` и `loadRaNums` — чанки по **500**.
3. `updateStagingRefs` — `executeBatch` каждые 500 строк.

Тот же код внесён в рабочую копию main и в worktree `femsq-hotfix-ralp-156`, ветка `hotfix/ralp-sql-2100-params-156` (база коммита 155, `1b4bd4b`). Сборка hotfix: thin **0.1.0.156** (`jar cfm`, в манифесте есть `Start-Class`). Тест `partitionForInClause_splitsAboveSqlServerLimit`: 2292 → 5 чанков, каждый меньше 2100.

## Сверка суммы «Принято затрат, руб.»

Колонка O листа «Аренда_Земли», заголовок «Принято затрат, руб.». Итог книги — `SUBTOTAL(9,O3:O1048576)`.

| Источник | Сумма |
|----------|------:|
| Числовые ячейки колонки O, 1677 шт. Совпадает с итогом Excel | 204 601 938,08 |
| Три текстовые ячейки, которые загрузчик разбирает как числа | 511 017,91 |
| `SUM(ralprtCostAndVat)` промежуточной таблицы локального прогона (exec_key 1220) | 205 112 955,99 |

Текстовые ячейки (`t="s"`). `SUBTOTAL` текст не складывает. `readDecimal` читает строку как сумму:

| Строка Excel | Отчёт | Текст в ячейке | Прочитано |
|--------------|-------|----------------|----------:|
| 725 | 686/300426 | `130,092,19` | 130 092,19 |
| 1974 | 1920/310826 | `4 677,62` | 4 677,62 |
| 1982 | 1929/310826 | `376 248,10` | 376 248,10 |

204 601 938,08 + 511 017,91 = 205 112 955,99.

Цифра экрана, названная в чате, **205 112 852,88** — на **103,11** меньше загруженной суммы. Эти 103,11 тремя текстовыми ячейками не объясняются. Локальный домен при сверке не перезаписывался.

Локальный прогон 15.10.2026: ревизия `test_26` (`adt_key=14`), AddRA выключен, UI `http://127.0.0.1:8080`. Файл `af_key=314` на время прогона указывал на снимок `2026-1014`. Type=5 (`af_key=312`) и type=6 (`af_key=313`) на время прогона были с `af_execute=0`, затем флаги возвращены. Лог: промежуточная таблица 2292, некорректных 30, RA добавлено 1842 / RA_AU добавлено 12 / RA_AU обновлено 3 — это счётчики dry-run, `обновлять БД = нет`, изменено строк = 0. Процесс JAR после прогона остановлен, порт 8080 свободен.
