## 0. Зачем

`_2606` — ключевой контур внедрения P2. Ошибки в нём недопустимы; O2 (помесячные планы) и отчёты C5 строятся вокруг него.

**Обнаружено (2026-11-27):** в mastering один параметр `@stNet` используется и как **IPG-net** (`ipgcStNetIpg`, часто **2**), и как **`@stCostNet`** для rollup плана/факта по структуре затрат. Рёбра канона 212→195/172/187 живут только в cost-net **3** («Стандартная»).

**Repro:** `iuplpmPlPn=7226`, месяц без строки 212, есть части:

| Вызов | Результат |
|-------|-----------|
| `fnStCostUtPlPMn(…, 212, **2**, mn)` | **0** |
| `fnStCostUtPlPMn(…, 212, **3**, mn)` | **Σ частей** |

Прямая строка на `stcKey` маскирует баг; sparse / только части → занижение до 0.

**Цель плана:** развести IPG-net и cost-net; default = боевая `stnType=2`; **проверить** возможность другой cost-сети (тест + cleanup); gates rollup; затем разблокировать C2 O2.
