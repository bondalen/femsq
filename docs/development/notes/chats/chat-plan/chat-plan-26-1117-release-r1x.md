## 2.4. Решение 2026-11-20 — выкладка R1.0 на прод отменена

| Довод | Суть |
|-------|------|
| Польза | R1.0 не даёт на проде новой бизнес-функции: типы 3/6 уже на 156, тип 5 — в Access. Цель — только проверка сосуществования |
| Два писателя | Тип 5 на проде пишет Access (`ra_change` = одно рассмотрение, без Au). Кандидат писал бы `ra_change_au`, зеркало на `ra_change` и версии `ra_change_summ`; apply одного перетирает зеркало другого. Синхронизация не делается |
| Расхождение моделей | Пример DEV: `rac_key=5668` — два рассмотрения с суммами 1 094 700,31 и −650 071,77; `_2605`/Access/`RRcTimeList` видят одну последнюю сумму |
| Откат | DDL аддитивна: `99_ROLLBACK` за минуты, 156/`_2605` таблицу Au не видят. Записи кандидата в `ra`/`ra_change`/`*_summ` скриптом не откатываются — разбор вручную |
| Вывод | Риски выкладки оправданы только при приёмке P2 на `_2606` на DEV целиком; на прод — один выпуск «Переключение R1» |

Прод до переключения: JAR 156 (исходники — тег `prod-jar-0.1.0.156`), Access, `_2605`. DDL `ra_change_au` на прод FishEye **не применять**.

## 3. Правила двух экземпляров

Основа — `.cursorrules` («Прод: два экземпляра приложения») и дорожная карта §3.

| Правило | Как выполняется |
|---------|-----------------|
| Свой каталог | `26-MMDD-R1.x` рядом с `26-0716-1600`; относительные `./reports`, `./temp` из `application.yml` у каждого свои |
| Свой `lib/` | Полный `lib/` кандидата; `lib/` действующего не трогать |
| Свой порт | По умолчанию 8080; кандидат — `--server.port=…` (номер — уточнить на проде, какой порт занят 156) |
| Свои логи | Каталог логов внутри каталога экземпляра |
| Остановка | Только своего экземпляра (по порту или PID). Скрипт `FEMSQ-остановка.bat` из пакета 156 ищет процессы по `femsq-web` / `JarLauncher` и **погасит оба** — для двух экземпляров не годится |
| Общая БД FishEye | DDL кандидата совместим с 156; приложение схему не мигрирует (Flyway/Liquibase нет) — только скрипты MSSQL2012 вручную |
| Подключение к БД | `~/.femsq/database.properties` общий для пользователя — оба экземпляра идут в одну БД |
| Ревизии | Один `af_type` не запускается одновременно из двух экземпляров |
| Критерий вывода | Записан в §2 п. 2.4 до выкладки кандидата |
