> **Зачем отдельный план.** За 3–5 месяцев работы по планам чатов JSON-файлы проекта (`project-docs.json`, `project-development.json`, `project-journal.json`, `modules.json`) и часть сопутствующих документов перестали отражать реальное состояние кода и прода. Этот план исправляет расхождения, меняет правила так, чтобы они не накапливались снова, и вводит автоматическую проверку `check-docs`.

## 0. Цель

1. Документация (JSON + основные документы) соответствует коду, проду и планам чатов на дату закрытия плана.
2. В правилах проекта есть точки синхронизации (когда и что обновлять), единые словари и автоматическая проверка, блокирующая коммит и сборку по ошибкам.
3. Доменные операции — только GraphQL: доменные REST-контроллеры удалены, исключения зарегистрированы, проверка в сборке не даёт появиться новым.
4. Есть сводный документ «Этапы пользователя» (P1 СУДЗ, P2 освоение лимитов, …) — каркас требований для трека C дорожной карты R1.

**Критерий закрытия:** `check-docs` — 0 ошибок; хук pre-commit и `build-thin-jar.sh` в блокирующем режиме; реестр расхождений §3 закрыт по каждой строке; план закрыт по новой процедуре (блок **14**).

**Не входит:** разработка трека C (ввод ИП/планов, факт, отчёты в FEMSQ) и выпуски R1.x — см. дорожную карту. Отложенная работа трека A (smoke, 21.5, флешка) — в [0604 v2](./chat-plan-26-0604-spMstrg-2606-v2.md), выполняется по порядку дорожной карты.
