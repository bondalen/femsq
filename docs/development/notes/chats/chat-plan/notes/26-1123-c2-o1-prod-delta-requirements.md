### 5.2 Алгоритм `ipgpSh` (решение владельца, 2026-11-23)

**Почему в эталоне почти нет `4`:** Excel **не содержит** схему реализации. На проде после вставки шла **пост-обработка**: (а) подстановка схемы из **предшествующей ИП** по `cstAgPn`; (б) позже — из **помесячного плана** (конечная истина, O2/LdM). Эталон = состояние **после (а)/(б)**, не сырой insert.

**Ограничение БД:** unique `(ipgpIpg, ipgpCstAgPn, ipgpSh)` — один `cstAgPn` + одна схема в одной ИП **один** раз. Если в Excel одна стройка в нескольких разделах → нужны **разные** `ipgpSh`, иначе ошибка.

**Целевой алгоритм FEMSQ (оптимизация vs «все с 4»):**

```text
Для каждой строки-стройки Excel в целевой ИП:
  1. Найти схемы этого cstAgPn в предшествующей ИП (если задана).
  2. Кандидат ipgpSh:
     · если cstAgPn встречается в файле 1 раз:
         предшествующая дала ровно 1 схему → взять её;
         иначе → 4 «Не определена».
     · если cstAgPn встречается N>1 раз (несколько разделов):
         назначить N различных схем:
           · сначала схемы из предшествующей ИП (если хватает);
           · недостающие — из свободных ключей ipgSh (в т.ч. 4),
             либо ERROR, если свободных схем не хватает.
  3. Проверка unique в пакете загрузки; конфликт → ERROR с перечнем cstAgPn.
После загрузки (отдельный шаг / тот же мастер):
  4. Для пунктов с ipgpSh=4 — ещё раз предложить схемы из предшествующей
     (если появился однозначный матч).
Позже (O2 / планы агентов):
  5. ipgpSh из помесячного плана перезаписывает как истина.
```

На DEV: обязательно завести `ipgSh` key **4**.

**Требование O1.2:** карточка `ipg` + цепь; bulk `ipgPn`+`ipgStPn` с алгоритмом выше; параметр «предшествующая ИП»; отчёт ошибок по unique/нехватке схем.

## 7. Действия, которые должен уметь повторить FEMSQ (чеклист DoD O1)

### Структура (O1.1)

1. **Клонировать** существующую сеть программно (`stNet` + членство `stNetPn`); затем **вручную** править дерево (перенос/добавление/удаление рёбер). Собирать сеть с нуля — вне основного сценария (дорого и ошибочно).  
2. Наполнить diff как на проде (пример: Харасавэй; замена детей «Безопасность»; дробление 2.1/2.2/2.3 на сети 5).  
3. Создать узлы + **все** варианты имён `stIpgNm` (в т.ч. с опечатками) — «рыбная ловля» из Excel.  
4. Превью сопоставления заголовков Excel → `stIpgNm` (нормализация + все aliases).  
5. UI для **несопоставленных** разделов: сопоставить с существующим узлом (добавить имя-alias) **или** создать новый узел+имя+ребро в текущей сети.

### Пункты (O1.2)

6. Создать `ipg` с `ipgStRlSh` = выбранная (обычно клонированная) сеть; цепь `ipgCh`.  
7. Staging → `ipgPn` + `ipgStPn`; `ipgpSh` по §5.2 (предшествующая ИП + 4 + unique).  
8. Не грузить суррогат `importIpgSt_*`.  
9. На DEV: `ipgSh` key 4.

Приёмка **не** MERGE эталона: сценарии sql_0→net4 / sql_iii→net5 на тестовых ключах; сверка дерева и unique логически с эталоном.
