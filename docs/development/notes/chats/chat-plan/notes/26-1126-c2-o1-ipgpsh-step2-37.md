# §3.7 Шаг 2 `ipgpSh` → `ag_*` / дозакрытие §3.6.4

**Дата:** 2026-11-26  
**План C2:** §3.7 (0.12.7)  
**Стенд:** `FishEye_prod_noM6` · цепь **507** · ИП **27–30**

## Диагноз

1. После O1 smoke на A все пункты были **`ipgpSh=4`**. В `fn2` схема `iShKey` для mastering не строится с 4 → в PercentBrn нет строк `typeGrTtl = '2. Агентская, план'` → **`ag_*` NULL**.
2. Даже после remap sh: **`fnStCostIpgPn_2606` читает только `ipgPnLim`**, не `ipgpSm*`. O1 писал Sm-колонки, **`ipgPnLim` на 27–30 = 0** (на эталонных ИП 1/3/5/6/8/11 `ipgplLim≈ipgpSmTtl`). Без lim `typeGrTtl` уходит в `1.2. Инв. (Аг., неплан)` → снова без `ag_*`.

## Политика хвоста

| Ситуация | `ipgpSh` |
|----------|----------|
| В prev=**26** ровно одна схема ∈ {1,2,3} | эта схема (`FROM_PREV`) |
| Иначе (нет / неоднозначно) | **2** (Агентская) |
| Массовый хвост **4** | **запрещён** до O2 |

Код: `DefaultImpIpgShResolveService.DEFAULT_UNDEFINED_SH = 2` (источник API `DEFAULT_4` = «default», значение ключа 2).
