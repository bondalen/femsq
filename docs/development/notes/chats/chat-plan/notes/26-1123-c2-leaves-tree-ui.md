## 1. Что показал Access

На карточке ИП оси **разные**, Access смешивает их вкладками под выбранной строкой `ipgPn`:

| Ось | Таблицы | Смысл |
|-----|---------|--------|
| **Пункт (лист ИП)** | `ipgPn` | стройка САК + схема реализации + суммы |
| **Структура ИПГ** | `ipgStPn` → `stIpg` | привязка к разделу DAG (не путать с затратами) |
| **Планы** | `ipgUtPl` → `Gr`/`GrP` → `ipgUtPlP` (`iuplpIpgPn`) | помесячный план по пункту |
| **Направления затрат** | `ipgUtPlPnLmYe/Qu/Mn`.`*StCost`, `ipgPnLim.ipgplStCost` | лимиты Ye/Qu/Mn и лимит пункта по `stCost` |

Плоский грид `Pn_t` + нижние вкладки — следствие bound-форм Access, не лучшая модель навигации. Тяжёлый Load полной `ipg` = подгрузка UtPl/Lm* при open (уже зафиксировано).

## 2. Предложение: `ipgPn` = корень декомпозиции

### 2.1 Экран Leaves (компоновка)

```text
[ список / выбор ИП ]     шапка ags.ipg (редактирование)
─────────────────────────────────────────────────────────
Лево: FemsqTree (пункты)     Право: карточка выбранного узла
  ├─ pn #1 стройка…            поля узла + действия
  │   ├─ Структура ИПГ  (lazy)
  │   ├─ Планы          (lazy, G3)
  │   └─ Лимиты/stCost  (lazy, G3)
  ├─ pn #2 …
  └─ …
```

- **Корни дерева** = строки `ipgPn` текущей ИП (не узлы `stIpg` — те на экране Structure).
- **Ветви 1-го уровня** = *папки-оси* (не сырые строки БД): `Структура` · `Планы` · `Лимиты`.
- **Глубже** — только после expand (lazy GraphQL), по оси.

### 2.2 Семантика узлов (kind)

| kind | Источник | Когда грузить | Этап |
|------|----------|---------------|------|
| `pn` | `ipgPn` | при открытии ИП (список корней) | **2.5.2** |
| `stBind` | `ipgStPn` | expand «Структура» | **2.5.2** |
| `folderPlans` / `folderLimits` / `folderStruct` | UI | сразу как leaf-folder под `pn` | **2.5.2** (папки) |
| `utPlP` | `ipgUtPlP` | expand «Планы» | **1.3 / 2.5.2 stub** |
| `lmYe` / `lmQu` / `lmMn` | `ipgUtPlPnLm*` | expand плана или папки лимитов | **1.3** |
| `pnLim` | `ipgPnLim` | expand «Лимиты» | **1.3** |

Папки `Планы`/`Лимиты` в 2.5.2 можно показывать **пустыми или с кнопкой «Загрузить…»** — без запросов UtPl при open карточки ИП.

### 2.3 Почему не один большой FemsqTable на 600+ пунктов без дерева

На скрине `ipgMin` у одной ИП **~612** пунктов. Таблица хороша для поиска/сортировки сумм; дерево лучше для **навигации по осям** выбранного пункта. Рекомендация — **гибрид**:

| Вариант | Суть | Плюс | Минус |
|---------|------|------|-------|
| **A. Дерево-first (рекомендуется)** | Корни = все `ipgPn`; filter по коду/имени; detail справа | Единый FemsqTree-паттерн с Structure; естественная декомпозиция | Много корней — нужен filter + виртуализация/свернуть всё |
| **B. Таблица + дерево detail** | FemsqTable пунктов; справа/снизу дерево осей выбранного | Привычный грид сумм; дерево не раздувается | Два виджета; слабее «пункт = корень» |
| **C. Только вкладки как Access** | Копия Pn_t + tabs | Минимум сюрпризов для оператора | Повторяет боль Access; хуже для UtPl lazy |

**Предложение по умолчанию: A**, с быстрым filter по `cstAgPnCode` / `ipgpTskCms`. Если оператору критичен табличный обзор сумм — добавить переключатель «таблица ↔ дерево» (A+B) без смены API.

### 2.4 Дерево (схема)

```text
ipgPn (корень)
├─ Структура ИПГ
│   └─ stiKey / имя раздела   ← ipgStPn (CRUD 2.4.2 уже есть)
├─ Планы                      ← lazy
│   └─ UtPlP (агент / дата / lim)
│       ├─ Год → stCost…
│       ├─ Квартал → stCost…
│       └─ Месяц → stCost…
└─ Лимиты пункта              ← lazy
    └─ stCost → lim           ← ipgPnLim
```

Важно: ветка «Структура ИПГ» — это **привязки**, не копия всего `fnSt`. Выбор раздела — picker из уже загруженной схемы Structure (`stIpgNetworks` / tree).

## 4. Ответы без скринов с прод (2026-11-23)

Владелец: пункты 1–4 закрываем по схеме/VBA/noM6, без новых скринов.

### 4.1 Ветка «Лимиты» (`ipgPnLim` / Access `Lim_t`)

| Поле | Смысл |
|------|--------|
| `ipgplKey` | PK |
| `ipgplPn` | → `ipgPn` |
| `ipgplStCost` | → `stCost` (`stcKey` = `stKey`) |
| `ipgplLim` | лимит |

В дереве под `ipgPn` → папка **Лимиты** → листья `stCost` (+ имя) / `lim`.  
Класс Access `ipgPnLim` отдаёт `stCost` через `ClassFactory.stCostByKey(ipgplStCost)`.  
**Объём:** CRUD/просмотр — этап **1.3**; в **2.5.2** — папка-stub (без загрузки строк при open).

### 4.2 Ветка «Планы»: Ye / Qu / Mn

Иерархия (не путать `ipgpKey` и `iuplpKey`):

```text
ipgPn
  └─ ipgUtPlP          (iuplpIpgPn = ipgpKey; PK = iuplpKey)
       ├─ LmYe         iuplpyPlPn = iuplpKey, iuplpyStCost, iuplpyLim
       ├─ LmQu         iuplpqPlPn = iuplpKey, iuplpqStCost, iuplpqQu, iuplpqLim
       └─ LmMn         iuplpmPlPn = iuplpKey, iuplpmStCost, iuplpmMn, iuplpmLim
```

VBA `Form_ipg>Pn_t>UtPlP_t`: при Current фильтрует три подформы по **`iuplpKey`**, не по `ipgpKey`.  
Sparse UtPl (Решение 10 / `_2606`): нет строки → лимит 0; ненулевые — только существующие строки.  
Канон stCost для `_2606`: **212 / 195 / 172 / 187**.  
**Объём:** expand Планы → UtPlP → Ye/Qu/Mn — **1.3**; в **2.5.2** — папка-stub + опционально кнопка «Загрузить планы» без edit.

### 4.3 Карточка / detail `ipgUtPlP`

Ключевые поля для UI (полный список колонок — в INFORMATION_SCHEMA; здесь ядро):

| Группа | Поля |
|--------|------|
| Связь | `iuplpKey`, `iuplpPl` (→ план), `iuplpIpgPn`, `iuplpSubAg` |
| Итог | `iuplpLim` |
| Кварталы | `iuplpQ1`…`Q4` |
| Месяцы | `iuplpM01`…`M12` (+ `*Accum` — производные, в 2.5.2 не править) |

В дереве: узел `utPlP` = одна строка плана; detail справа — Lim + Q + M (read-only stub → edit в 1.3).  
Разбивка по stCost **не** в самой `ipgUtPlP`, а в дочерних `Lm*`.

### 4.4 Как показывать имя `stCost`

- Источник: `ags.stCostNm` (`stcnCost`, `stcnNm`, …) — **несколько имён на один** `stCost` (как `stIpgNm`).
- В UI Leaves/лимитов: **`stcKey` + одно отображаемое имя** (правило как у Structure: `MIN(stcnKey)` / «текущее» — зафиксировать при GraphQL 1.3; до этого в stub достаточно `stcKey` + любое `stcnNm` через `MIN`).
- Подпись в дереве: `195 · СМР` (пример); для канона подписывать известные 212/195/172/187 явно в подсказке, не хардкодить только их в CRUD.

### 4.5 Следствие для 2.5.2

Скрины прод по 1–4 **не требуются**. Старт UI: корни `ipgPn` + папки Structure/Планы/Лимиты; заполнена только Structure (`ipgStPn`); Планы/Лимиты — lazy stub до блока 4.
