## Цель O2

На DEV (`FishEye_prod_noM6`) оператор видит и вводит **помесячные планы/лимиты** по stCost (212/195/172/187), достаточные для осмысленного `_2606` с ненулевым планом (не только lim/факт).

## 1. Канон-зерно (§4.00.5 ✅)

Единица хранения / записи для FEMSQ O2 и расчёта `_2606`:

```text
(agent/ipg, scheme∈{АД,ИД,…}, cstAgPn → ipgPn, stCost∈{212,195,172,187}, month∈1..12, measure∈{plan,lim})
  → decimal(23,8)   только через FemsqMoney / AggAxis
```

| Ось | Минимум (обязателен) | Канон хранения | Агрегаты |
|-----|----------------------|----------------|----------|
| **S** Scope | агент → схема АД\|ИД → объект | `ipgUtPl` / `ipgpSh` / `ipgPn` | Σ объекты→схема→агент |
| **C** Cost | `212 = 195+172+187` | `ipgUtPlPnLmMn` (+ год `LmYe` / `ipgPnLim`) | Σ части→212 |
| **T** Time | 12 месяцев | `iuplpmMn` 1…12 (sparse >0) | Σ M→Q→Y; Q/Year — производные |
| **M** Measure | plan / lim | те же таблицы; lim года ↔ `iuplpLim` / `ipgPnLim` | — |

**Не в зерне O2:** филиал multi (Решение 013); facety шаблона (подрядчики / виды работ / подобъекты) — презентация Excel, опционально позже; highlight «в т.ч. АВ» ⊆ 187 — **не** 4-е слагаемое 212.

**Шире Access LdM:** канон FEMSQ пишет **`ipgUtPlPnLmMn` @ stCost**; Access G2 пишет только широкие `ipgUtPlP` (семантика **212**). O2 UI/G3 обязан закрыть разрыв C.

### Агрегация (рёбра)

| Ребро | Правило |
|-------|---------|
| C: PART → TOTAL | `195+172+187 = 212` (AggAxis; ADR 012) |
| T: M → Q → Y | `ΣM квартала = Q`; `ΣM года ≟ limYear` (DoD B: Q→δ в M12) |
| S: объекты → итого АД\|ИД | Σ partition (мера × месяц × stCost) |
| S: АД + ИД → агент (файл раздела) | Σ |
| S: раздел → ИП / `@ipgStKey` | через `stIpg` + `ipgStPn` / `fnIpgChContractsForStIpg_2606` (**не** сумма «двух Excel» вслепую) |

Типы рёбер Excel: **partition** · **highlight** · **facet** — в канон O2 импортируются только partition тройки+212 и месяцы.

### Роли строк Excel (для будущего парсера / UI)

| Роль | Примеры | Действие |
|------|---------|----------|
| `TOTAL` | Всего по стройке / итого схемы | авторитет Ttl/212 или Σ частей |
| `PART` | СМР/195, Оборудование/172, Прочие/187 | части тройки |
| `HIGHLIGHT` | в т.ч. АВ | не аддитив к 212 |
| `FACET_*` / `LABEL` | подрядчики, «в том числе:» | вне канона O2 `_2606` |

## 3. Деньги / оси — DoD записи ✅ 2026-11-27

Канон — [ADR 012](../../../../project/decisions/012-money-agg-axes.md) / §6 **0095**. Лист Excel `копейки` (051) — не вход парсера.

### A. Поток на любой записи UtPl/lim (UI GraphQL → `ipgUtPlP` / `LmMn` / seed lim)

1. `FemsqMoney.roundMln` на каждое число (scale **8**).  
2. `AggAxis` на осях **C** и **Sm** (`Ttl=Wrk+Equ+Oth`), если ось есть в зерне.  
3. Классы δ: **Q/A** — autofix + лог; **A-hard** — block; **S** — не выдумывать разбивку.  
4. Обход util **запрещён**.  
5. Gate **G-agg:** после записи `COUNT(δ≠0)=0` (класс 07k1).

### B. Ось T

| | |
|--|--|
| Инвариант | `Σ M01…M12 ≟ limYear` (и Q↔M, если Q хранятся) |
| **Q** | авторитет года / `iuplpLim`; δ → **M12** |
| **A** | сумма месяцев → пересчёт года |
| **A-hard** | block |
| **S** | не авто-разбивать пустые месяцы |

### C. Gates vs годовая ИП

| Gate | Смысл | Когда |
|------|--------|--------|
| **G-agg** | оси UtPl согласованы | DoD каждой записи (§4.2) |
| **G-ip** | Σ UtPl (год @212) ≈ `ipgPnLim` / Sm пункта | §4.3 и LdM (§6); без тихого fix Excel |

### D. Excel LdM (§6 C2)

Access: `Round(,8)` → широкие 212-поля. FEMSQ LdM: pipeline **A+B**; `копейки` не парсить — диагностика **G-ip**.

## 5. Access LdM (факт G2)

`Form_ipg>LdM_t`: плоская строка объекта → **`ipgUtPlP`** (`iuplpLim`/`M*`/`Q*`, семантика **212**). Схема из `ipgLdm_fSh`. **Не** пишет `LmMn` / 195/172/187; **не** читает филиал.  
Подробно: [template-study §Access LdM](./26-1127-c2-o2-utpl-template-study.md#access-ldm-какие-поля-excel-реально-читаются-2026-11-27).

Итог для FEMSQ: перенос LdM = конфиг листа + якоря + диапазоны схем + плоская строка; ось C@stCost — **отдельный** контур (UI G3 / парсер), не копия Access-load.
