## §4.00.2 Ось T — время (шаблон 000) ✅

Колонки Прил.1 (лист `Лист1`):

| Кол. | Роль |
|------|------|
| **D** | Утверждённый **лимит** года (`limYear` утв.) — мера **lim**, не план |
| **E** | Уточнённый лимит года (`limYear` корр.) |
| **F / J / N / R** | **Всего** квартала I…IV — partition Σ месяцев квартала |
| **G–I, K–M, O–Q, S–U** | Месяцы **M01…M12** |

```text
M01+M02+M03 = Q1.Всего
… 
Q1+Q2+Q3+Q4 = Year(plan)     (если заполнены все «Всего»)
limYear  ⊥  Year(plan)       (разные меры; сверка — отдельный gate)
```

В реальных файлах квартальные «Всего» могут быть формулами (`=SUM` месяцев) или опущены при наличии 12 месяцев — для O2 канон хранения = **месяц**; квартал/год — агрегаты AggAxis.

## §4.00.3 Ось C — затраты (шаблон + минимум) ✅

### Идеал шаблона 000 (на каждом узле Scope)

| Уровень | Узлы | Тип ребра |
|---------|------|-----------|
| Итог | **Всего** ↔ stCost **212** | partition ← 195+172+187 |
| Тройка | Подрядные/СМР **195**, Оборудование **172**, Прочие **187** | partition |
| Highlight | «в т.ч. АВ» ⊆ 187 | **не** 4-е слагаемое 212 |
| Facet (195) | по подрядчикам **или** по видам работ | альтернативы, не обе в сумму |
| Detail (172/187) | виды затрат (логистика, ГРО, ПНР…) | partition внутри ветки |
| Подобъект | повтор того же C-DAG | расширение S, не C |

### Минимум в реальных планах (014 / 051 / 060)

Обязательно: **`212 = 195 + 172 + 187`** (в Excel: Всего / СМР|Подрядные / Оборудование / Прочие) на объекте × месяц (и на итогах схем).

Часто есть: АВ как highlight; у 014 — более длинный список статей под Equ/Oth; у 060 — статьи ПИР-блока + коды 1/2/3/4 на АД.

Обычно **нет** (сокращено относительно 000): полноценные блоки подрядчиков, подобъектов, полной таксономии видов работ.

Роли строк (для парсера):

| Роль | Примеры | Действие импорта |
|------|---------|------------------|
| `TOTAL` | Всего по стройке / итого схемы | авторитет Ttl/212 или Σ частей (ADR) |
| `PART` | СМР, Оборудование, Прочие | части тройки |
| `HIGHLIGHT` | в т.ч. АВ | не аддитив к 212 |
| `FACET_HDR` / `FACET_LEAF` | подрядчики, виды работ | вне канона O2 `_2606` (опц. позже) |
| `LABEL` | «в том числе:» | пропуск |

### Филиалы (051-2\*\*\*\*\*\*) — решение 2026-11-27 ✅

Не ось шаблона 000. У агента **051** стройки разносятся по **филиалам** (`Свод!Филиал`, лист `branch`: `cstAgPn → ogBranch`).

- **1 ipgPn ↔ 1 филиал** — норма модели и O2.  
- **Разделение лимита** одной стройки/пункта на **>1 филиал одновременно** — **не поддержано** ни в lim/UtPl, ни в Access LdM, ни в `_2606` (есть только календарь `cstAgPnBranch`).  
- **Принято (Решение 013):** в O2 **не** реализовывать; **обход** — суммировать доли к **филиалу с большей суммой** (как подготовка на `двоящуры`: `051-2001182`, `051-2000618`, `051-2000961`). Полная поддержка — отдельная будущая задача «загрузка + `_2606`/`_2***`».  
- Глоссарий: [разделение лимита пункта ИП по филиалам (multi)](../../../../project/glossary.md); проблема `P-2026-11-27-001`.

### Копейки / R-MONEY-AGG — решение 2026-11-27 ✅

Новой политики нет: канон [ADR 012](../../../../project/decisions/012-money-agg-axes.md) / §6 **0095**. Лист **`копейки`** (051) — артефакт подготовки Excel, не вход LdM.

## Access LdM: какие поля Excel реально читаются (2026-11-27)

Источник: `Form_ipg>LdM_t` (`docs/project/proposals/vba-analysis/VBA-Code-Export/Form-Modules/Form_ipg_gt_LdM_t.cls`).  
Это **G2** (уточнённые планы), не годовая ИП O1.

### Способ

1. Сессия `ipgLdM` → файлы `ipgLdM_f` (путь, лист, флаги) → диапазоны схем `ipgLdm_fSh` (`ldmfsStart`…`ldmfsEnd`, `ldmfsScheme`→`ipgSh`).  
2. Excel COM: открыть книгу → лист `ldmfSheet` → снять AutoFilter.  
3. Найти якоря **поиском по тексту** (не фиксированные буквы колонок шаблона):  
   - код: `Код стройки` / `Код` / `Код ИП` / `Код объекта/стройки` / `Код объекта (ИУС)`;  
   - лимит года: подстрока **`ldmfLimColumn`** (настройка файла).  
4. В каждом диапазоне схемы — `Find` маски **`???-???????`** в колонке кода.  
5. На найденной строке читать числа **смещениями** от колонки лимита; `Round(..., 8)`.  
6. Сопоставить `cstAgPn` + лимит года с `ipgPn` (`ipgpSmTtl`); писать/сверять **`ags.ipgUtPlP`**: `iuplpLim`, `iuplpQ*`, `iuplpM01…M12`; при Update — ещё `ipgpSh` ← схема диапазона.

### Поля Excel → использование

| Что в файле | Как Access берёт | Куда пишет |
|-------------|------------------|------------|
| Код `NNN-NNNNNNN` | колонка якоря «Код…», маска | `idmfscCst` → `cstAgPn` / `ipgp` |
| Имя (соседняя справа от кода) | `Offset(0,1)` | **фильтр:** если имя ∈ `ags.ipgCostItsNmAll` → строка **не стройка** (направление затрат), **не грузится** как объект; подрядчик в комментарии VBA «ещё бы проверить» — **не реализовано** |
| Лимит года | колонка `ldmfLimColumn` (`ddOffset` от кода) | `ldmfscLim` → сверка/`iuplpLim` |
| Кварталы + месяцы **или** только 12 мес. | `ldmfQuarter` + `ldmfSumFirst`: от колонки лимита цепочка смещений | `ldmfscLimQu*` / `LimMn*` → `iuplpQ*` / `iuplpM*` |
| Схема АД/ИД/… | **не из Excel**, а из `ipgLdm_fSh.ldmfsScheme` (ручные диапазоны строк) | `ldmfscScheme` → при Update `ipgpSh` |
| Филиал | **не читается** | — |
| СМР / Оборудование / Прочие (строки PART) | только отсев по имени в `ipgCostItsNmAll`; суммы частей **не** пишутся в UtPl | — |
| Глубина шаблона (подрядчики, подобъекты) | не используется | — |
| Листы `branch` / `копейки` / `двоящуры` | не в коде LdM (ручная подготовка файла) | — |

### Раскладка колонок сумм (два режима)

Задаётся на файл: `ldmfQuarter`, `ldmfSumFirst` (смещение **первой** суммы плана от колонки годового лимита).

| `ldmfQuarter` | Порядок после `Offset = ddOffset + ldmfSumFirst` |
|---------------|--------------------------------------------------|
| **True** (как шаблон 000 / Прил.1) | Q1, M01, M02, M03, Q2, M04…M06, Q3, M07…M09, Q4, M10…M12 (**16** чисел) |
| **False** (как плоский `Свод` 051) | M01…M12 подряд (**12** чисел) |

Шаблон 000: лимит утв. **D**, уточн. **E**, затем F=Q1 / G–I месяцы… — оператор в Access выбирает, **какая** колонка = `ldmfLimColumn` и какой `SumFirst` (часто уточнённый лимит + сдвиг к первому «Всего»/месяцу).

### Что **не** делает Access LdM (важно для O2)

- Не наполняет **`ipgUtPlPnLmMn`** / разбивку **195/172/187** — только широкие поля **`ipgUtPlP`** (= семантика **stCost 212**).  
- Не знает филиал и multi-branch.  
- Не парсит иерархию C шаблона; минимум «Всего=СМР+Оборуд+Прочие» в Excel для LdM **не обязателен** — достаточно строки объекта с кодом, годовым лимитом ≠0 и месяцами.

Итог для FEMSQ: перенос LdM = конфиг листа + якоря + диапазоны схем + плоская строка объекта; ось C@stCost — **отдельный** контур (UI G3 / будущий парсер), не копия текущего Access-load.

## Scope — два уровня (зафиксировано 2026-11-27)

### A. Разделы структуры инвестпрограммы (`stIpg` / `stNetIpg`)

**Стройки** и **ПИР** — не группы внутри Excel-файла плана, а **элементы DAG разделов ИП** (`ags.stIpg`, привязка пункта через `ipgStPn`). Тип объекта по коду САК — 5-я литера `cstapIpgPnN` (`ags.fnCstAgPnTypeChar`, glossary / Решение 16).

| Смысл | Узел `stIpg` | Где живёт | `typeChar` / пример |
|-------|-------------|-----------|---------------------|
| План КС | **2** | корень ветки | — |
| Структура **видов** | **52** | под 2 | явная нарезка |
| **Стройки** (имя в дереве) | **56** | под 52→54 | **`2`**, `001-2001234` |
| **ПИР** | **45** | под 54 **и** под 53 | **`1`**, `001-1001234` |
| Структура **целей** | **53** | под 2; **Excel ИП** | без узла «Стройки» |
| КС без ПИР (`_2606`) | **51** | **не** в сетях ИП | OutLim `2`+`3` |

### Две «структуры» под Планом КС (владелец + DBHub 2026-11-27)

Актуальная выгрузка 26-III: шара `excel/2026-1127/ipg-st-26-III/` (`stNet>fnSt_t`). Под **`2`** всегда две ветки:

| Ветка | `stiKey` | Имя | Роль |
|-------|----------|-----|------|
| **Виды** | **52** | Структура видов… | Явно отделяет **`56` Стройки** (`typeChar=2`) от **`45` ПИР** (`typeChar=1`) под `54` Промстроительство |
| **Цели** | **53** | Структура целей… | Формат **наших Excel ИП** (O1 `sql_*`, пути вида «Приоритетные проекты»…); отдельного узла «Стройки» нет; **`45` ПИР** включён **повторно** |

```text
2  План капитального строительства
├─ 52  Структура видов
│  └─ 54  Промстроительство
│     ├─ 56  Стройки      ← xxx-2……
│     ├─ … ГРР / бурение / оборуд.
│     └─ 45  ПИР и РД     ← xxx-1……
└─ 53  Структура целей          ← Excel ИП FEMSQ/O1
   ├─ 3 / 23 / 38 / 66 …        (приоритетные, КЦП, прочие…)
   └─ 45  ПИР и РД              (тот же stiKey, другое ребро)
```

**Сети, присвоенные ИП** (`ipg.ipgStRlSh` ∈ {1,2,5,6} на noM6): в **2/5/6** есть и `2→52`, и `2→53`, и `56`, и оба вхождения `45`. Узел **`51` ни в одной** из этих сетей **не состоит** (`stRel`/`stNetPn` с 51 = 0).

**Узел `51` «План КС без ПИР»** — не раздел дерева ИП, а **фильтр `_2606`**: `stiLim=2` + `stIpgOutLimPn` типы **`2`,`3`** (стройки+бурение, **без** ПИР `1`). Смысл: `@ipgStKey=51` → расчёт «вся ИП кроме ПИР», даже если `ipgPn` ПИР внесены. На ИП 27–30 в `ipgStPn` узлы привязки — листья/ветки **целей (53)**; **51 и 56 в привязках не встречаются**.

| Термин | Что это |
|--------|---------|
| «Стройки» в **дереве видов** | **`56`** |
| Excel ИП / O1 (цели) | ветка **`53`**; стройки vs ПИР — по **`typeChar`**, не по узлу 56 |
| «Стройки без ПИР» для отчёта `_2606` | **`51`** (OutLim), не член сети |

### B. Сегмент внутри файла раздела (агент × договор)

Для **одного** файла одного раздела (сейчас — Стройки) каркас охвата:

```text
1. Агент                          (файл / ipgUtPl.iupl… на текущую ipg)
├─ 1.1. итого АД
│  └─ объекты раздела             (для Строек: typeChar=2, напр. 001-2001234)
│     ├─ 001-2001234
│     └─ 001-2001235
└─ 1.2. итого ИД
   └─ объекты раздела
      ├─ 001-2002234
      └─ 001-2002235
```

Ранее в черновике под АД/ИД стояли вложенные ярлыки «Стройки|ПИР» — **снято**: Стройки/ПИР живут в **§A (stIpg)**; внутри файла — объекты **текущего** раздела. Симметрия АД/ИД для файла ПИР — при изучении того Excel.

**Прочее**

- Префиксы агентов в пакете 26-III: **014 / 051 / 060**.
- На объекте (и итогах) **повторяются** оси **C** (212/195/172/187…) и **T** (месяц/квартал) — не расширение Scope.

### Агрегация по Scope (ожидание)

| Ребро | Правило |
|-------|---------|
| объекты → итого АД\|ИД | Σ partition (мера × месяц × stCost) |
| итого АД + итого ИД → агент (файл раздела) | Σ |
| раздел Стройки ∪ раздел ПИР → ИП / отчёт `@ipgStKey` | через `stIpg` + `ipgStPn` / `fnIpgChContractsForStIpg_2606` (не сумма «двух Excel» вслепую) |
