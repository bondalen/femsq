## 0. Карта экранов (операторский контур 1.1)

```text
Структура ИПГ (G4)                    Карточка ИП (G1)                 Цепь (G1)
─────────────────                     ───────────────                  ────────
stNetIpg                              ipg / ipgMin / ipgMinBranch      ipgCh / ipgChMin
  ├─ список схем (ags.stNet, type=1)    ├─ шапка ИП (ags.ipg)            ├─ шапка цепи (ags.ipgCh)
  ├─ дерево fnSt (stNet>fnSt_t)         ├─ список пунктов ipg>Pn_t       ├─ связи ipgCh>Rl_t
  └─ (карточка узла) stIpg*             ├─ карточка пункта ipg>Pn_f      ├─ пункты late-ИП ipgCh>ipgPn_t
       Nm / parent / child / stNetPn    │    └─ ipg>Pn_f>StPn (узел)     └─ [кнопки освоения — вне 1.1 UI]
                                        └─ [вкладки UtPl/LdM — G3/G2]

Legacy (не целевой контур FEMSQ): ipgSt* / ipgStRlSh*  → семейство без FK к ipgPn (см. §3)
```

Порядок работы владельца (§2.0c): **Structure → Leaves** — сначала схема/`stIpg`, затем пункты/`ipgPn`+`ipgStPn`.

## 1. G1 — карточка инвестпрограммы

### 1.1 Оболочки

| Форма | VBA | Роль (владелец, 2026-11-20) |
|-------|-----|----------------|
| `ipg` | `Form_Current`: sync Pn_t → Pn_f | **Эталон карточки ИП** — полный функционал (в т.ч. проверки помесячных планов). Сейчас Load медленный из‑за неоптимизированных запросов; в FEMSQ — тот же объём, но проверки **оптимизировать** (не выкидывать) |
| `ipgMin` | тот же sync | Урезанный обход: почти как `ipg`, без тяжёлого блока UtPl. Ушли **второпях** из‑за тормозов; не целевой UX |
| `ipgMinBranch` | тот же sync | **Не использовать** — давно не применяется |

Все три — **master**: при смене текущей строки / текущего пункта в гриде фильтруют деталь:

```vb
Me![ipg>Pn_f].Form.Form.Filter = "ipgpKey = " & ipgpKey
```

То же делает `ipg>Pn_t`.Form_Current через `Me.parent![ipg>Pn_f]`.

### 1.2 Подформы на карточке ИП (ядро 1.1)

| Подформа | Код | Что видит оператор | Пишет в БД (ожидание) |
|----------|-----|--------------------|------------------------|
| `ipg>Pn_t` | VBA sync | Табличный список пунктов текущей ИП | `ags.ipgPn` (bound) |
| `ipg>Pn_f` | bound | Карточка выбранного пункта (суммы, схема `ipgpSh`, …) | `ags.ipgPn` |
| `ipg>Pn_f>StPn` | bound | Привязка пункта к узлу структуры | `ags.ipgStPn` (`ipgspPn`, `ipgspSt`→`stIpg`) |
| `ipg>Pn_f_Branch` | bound | Branch-вариант карточки пункта | `ags.ipgPn` (?) |
| `ipg>ChRl_t` | bound | Связи ИП в цепи (?) | `ags.ipgChRl*` |
| `ipg>ipg1` | VBA → LdM | Мост к загрузке Excel | **G2**, не ядро 1.1 |

**Вне ядра 1.1 (на тех же оболочках, разбор позже):**  
`ipg>Pn_f>Lim_*`, `…UtPlPnLm*`, `ipg>Pn_t>UtPl*`, `ipg>UtPl*` → **G3**; `ipg>LdM_*` → **G2**.

### 1.3 Поля шапки ИП (из `ags.ipg` / класса `ipg`)

Оператор правит (bound + класс-геттеры): `ipgNm`, `ipgYy` / `ipgYyYear`, `ipgNum`, `ipgOg`, `ipgStr`/`ipgEnd`, `ipgStRlSh` → **схема `stNet`**, `ipgRepl`.  
Ключ: `ipgKey`. Linked: `ags_ipg`.

### 1.4 Поля пункта (из `ags.ipgPn`, эталон/схема 02)

Грид/карточка: `ipgpNum`, `ipgpCstAgPn` (стройка САК), суммы `ipgpSmTtl|Wrk|Equ|Oth|AgFee|CostAdjust|SmReserv`, `ipgpTskCms` (ввод мощности, бывают `\n`), `ipgpSh` → `ags.ipgSh` (на проде есть ключ **4 = «Не определена»**).  
Уникальность: `(ipgpIpg, ipgpCstAgPn, ipgpSh)`.

## 2. G1 — цепь инвестпрограмм

### 2.1 Оболочки

| Форма | VBA | Назначение UI |
|-------|-----|----------------|
| `ipgCh` | много кнопок + `Form_Current` | Полная цепь |
| `ipgChMin` | то же + `Form_Load` (месяц `cbxMounth`), `btnMasteringPercent_2408` | Рабочая «Min»-цепь (обновлялась 2026-11-17) |

**Шапка (bound `ags.ipgCh`):** `ipgcKey`, `ipgcName`, `ipgcYyyy`, `ipgcStNetIpg` → схема структуры, `ipgcIpgLate` → актуальная ИП в цепи.

### 2.2 Подформы

| Подформа | Код | Роль для 1.1 |
|----------|-----|--------------|
| `ipgCh>Rl_t` | bound | См. **§2.4** — грид членства ИП в цепи (`ags.ipgChRl`) |
| `ipgCh>ipgPn_t` | bound | Пункты late-ИП (фильтр из G2 `impNewSumCompare`) — просмотр/сверка |
| `ipgCh>ra_chSmLt_*` | bound | Суммы RA по цепи — **факт, не 1.1** |
| `ipgCh>Rslt_d_t`, `ipgChRslt>Full` | bound + кнопки | Локальные таблицы освоения — **C3/G8**, не CRUD 1.1 |

### 2.4 Что такое `ipgCh>Rl_t` (пояснение)

Имя: **Rl** = Relation (связи), **_t** = table (табличный вид). Это **не** рёбра структуры ИПГ (`stRel` / дерево на `stNetIpg`).

Подформа на карточке **цепи** (`ipgCh` / `ipgChMin`): показывает и правит строки **`ags.ipgChRl`** — «какие ИП входят в эту цепь и с какой группой планов».

| Колонка | Смысл |
|---------|--------|
| `ipgcrKey` | ключ строки |
| `ipgcrChain` | цепь (`ipgCh.ipgcKey`) |
| `ipgcrIpg` | инвестиционная программа в составе цепи |
| `ipgcrUtPlGr` | группа планов UtPl (может быть NULL) |

Пример (noM6, цепь 15): ИП 25↔gr17, ИП 26↔NULL.

В FEMSQ это уже видно **только чтением** на экране «Цепочки инвестиционных программ» → деталь «связанные программы» (`investmentChainRelations` ← те же поля). В Access оператор **добавляет/меняет** эти строки вручную на `ipgCh>Rl_t` (или аналог на `ipgChMin`).

Отдельно: для `_2606` календарь актуальности ИП — таблица **`ipgChRl_2606`** (с датами); legacy `ipgChRl` — членство без дневной гранулярности. Для UI ввода 1.1 сначала членство (`ipgChRl`); даты `_2606` — при касании C3/миграции.

### 2.3 Кнопки (осознанно вне объёма UI ввода 1.1)

`btnMasteringCst`, `btnMasteringPercent` / `_2408`, `Кнопка11/53/57` — тянут `ags.ipgChRslt*` / `spIpgChRslt*` / `spMstrg_*` в локальные Access-таблицы. Для FEMSQ 1.1 **не воспроизводить**; в FEMSQ это контур отчётов/освоения (C3/C4).

## 3. G4 — структура ИПГ (`stNet` / `stIpg`)

### 3.1 Актуальное семейство (целевой UI)

| Форма | VBA | Поведение |
|-------|-----|-----------|
| `stNetIpg` | `Form_Activate` / `Form_Current` | **Целевой хаб** (владелец). Caption UI: «Схема связи пунктов инвестпрограммы». Вкладки: **структура** / **инвестпрограммы** / **общее**. Список схем `stnName` (на скрине — «2026-06, разблокированная», type=`стр. инвестпрог`, корень=`Вся`). Пересобирает `ags.fnSt(stnKey, stnRoot)` → грид `stNet>fnSt_t` |
| `stNet>fnSt_t` | `Form_Current` | Грид обхода: `strChild`, `strPa`, `stpnN`, `pnL`, `stNum`, `Nm` (скрин: 90 строк). **Внимание VBA:** фильтр на `stNetCost>stCost` (для затрат); на `stNetIpg` из‑за `On Error Resume Next` не ведёт карточку узла |
| `stIpg` + `Nm` / parent / child / `stNetPn` | bound | **CRUD вершин и рёбер** — отдельные формы; владелец: «в идеале всё через `stNetIpg`, сейчас приходится мучиться с другими формами» |
| `stNetIpg>ipg_t` | bound | Вкладка «инвестпрограммы» — ИП, привязанные к схеме |

**Следствие для FEMSQ:** один экран Structure должен совмещать то, что в Access размазано: просмотр `fnSt` **и** CRUD `st`/`stIpg`/`stIpgNm`/`stRel`/`stNetPn` без прыжков по формам. Новая схема — на практике **копия+правка** (сборка с нуля «огромный труд»; точный рецепт лета 2025 владелец не вспомнил — восстановить на 2.2/приёмке).

Параллель затрат (`stNetCost` / `stCost*`) — **тот же паттерн UI**, но по §2.0c отложена к этапу **1.3** (не блокирует 2.1).

### 3.2 Legacy UI (не переносить как основу)

| Форма | Примечание |
|-------|------------|
| `ipgSt`, `ipgSt>Pn`, `ipgSt>Rl_*` | Семейство `ags.ipgSt*` **изолировано** (нет FK к `ipgPn`/`ipgStPn`) |
| `ipgStRlSh` (+ `fnIpgStNumSm`, `ipg_t`) | Старая «схема»; VBA похож на `stNetIpg`, но функция `ags.fnIpgStNumSm` по legacy |

Для FEMSQ ориентир — **`stNetIpg` + `stIpg*` + `fnSt`**, не `ipgStRlSh`.

## 5. Следствия для FEMSQ UI (черновик под 2.3–2.5)

1. **Два мастера/экрана:** (A) Structure = схемы + дерево + карточка узла; (B) Leaves = ИП + грид пунктов + привязка `stiKey` + цепи.  
2. Дерево = результат `fnSt(stnKey, stnRoot)` (как Access), не плоский lookup.  
3. Карточка пункта: поля как в эталоне `ipgPn.tsv`; `ipgSh` со значением по умолчанию «Не определена» при загрузке.  
4. Не тащить в 1.1 кнопки освоения и вкладки UtPl/LdM.  
5. UX карточки ИП в FEMSQ — от полной **`ipg`** (весь функционал). Проверки UtPl/планов **оставить**, но оптимизировать (не Load-убивающие запросы Access; ленивый/по действию запуск — допустим, если сохраняется покрытие). `ipgMin` — не эталон.  
6. Structure в FEMSQ — **единый** CRUD вокруг модели `stNetIpg`+`fnSt`, чтобы не повторять боль Access с отдельными `stIpg*`.
