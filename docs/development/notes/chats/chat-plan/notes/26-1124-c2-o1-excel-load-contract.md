## 1. Два артефакта (не путать)

| Артефакт | Роль |
|----------|------|
| **`ags.impIpg`** (+ при необходимости дети) | **Тело** разбора Excel: парсер пишет сюда содержимое максимально полно; процесс загрузки «кормится» отсюда и дополняет полями распознавания (`stiKey`, пути, …) |
| **`ags.impIpgLoad`** (+ дети) | **Управление процессом** загрузки: пути к файлам, статусы, связь с `ipg`, строки помесячных файлов, маппинг колонок и пр. |

Исторический Access: `ipgLdM` / `ipgLdM_f` / `ipgLdm_fSh*` — прообраз ТГФЭП только для **уточнённых** планов (G2). Для **годовой** ИП в Access отдельного корня не было (SSMS → `impIpg_YYYY-N`). В FEMSQ единый корень закрывает оба потока.

**Не путать с** доменной **группой планов** `ags.ipgUtPlGr` (набор `ipgUtPl` для `_2606` через `ipgChRl` / `_2606`).

## 2. Именование и связи

```text
ipg
 ├─ ipg.ipgStRlSh → stNet          ← единственный выбор схемы структуры
 ├─ impIpgLoad (1..*)              ← сессии загрузки этой ИП
 │    ├─ путь к Excel годовой ИП (и метаданные сессии)
 │    ├─ → ags.impIpg…             ← тело парсера / ПТСФ / листья
 │    └─ impIpgLoadMonf (0..*)     ← помесячные файлы агентов
 │         └─ → ipgUtPl
 └─ (через цепь) ipgChRl(_2606).…UtPlGr → ipgUtPlGr ← GrP → ipgUtPl
```

| Таблица | Смысл |
|--------|--------|
| **`ags.impIpgLoad`** | ТГФЭП — корень загрузки под `ipg` |
| **`ags.impIpgLoadMonf`** | строка помесячного Excel агента; `impIpgLoad` **1:\*** `Monf` |
| Дальше | колонки/дети добавляются по мере разработки (маппинг Excel→`ipgPn`, JSON-контекст пути, …) |

Операционно у одной ИП обычно **много** `Monf` (файлы с агентов). Один `Monf` на ИП — аномалия, не запрет схемы.

Несколько **`impIpgLoad` на одну `ipg`** — разрешено (исправления файла / смена выбора). Флаг «активная» не нужен: UI работает **в контексте выбранной** записи load (как Access `ldm*` на вкладке загрузки).

## 3. `stNet` — одно место истины

| Место | Роль |
|-------|------|
| **`ipg.ipgStRlSh`** | оператор выбирает схему здесь |
| `impIpgLoad` | **не хранит** свой `stNet` (при необходимости — computed/read-only от `ipg`) |
| `ipgCh.ipgcStNetIpg` | **computed** от членства (уже в FEMSQ) |

Все загрузки одной ИП используют **одну** структуру. Смена `ipgStRlSh` при уже закрытой сверке / загруженных `ipgPn` — **предупреждение** (не жёсткий запрет). Без `ipgStRlSh` загрузка пунктов запрещена.

## 4. Порядок оператора

```text
Материалы: Excel годовой ИП + комплект Excel помесячных планов агентов

── Этап 1 (O1) — годовая ИП ───────────────────────────────
  1. Создать ipg (задать ipgStRlSh)
  2. Создать impIpgLoad под ipg (путь к файлу)
  3. Сверка структуры (экран Structure) + загрузка пунктов → ipgPn (+ ipgStPn)
  До завершения этапа 1 загрузка Monf бессмысленна:
  помесячный план садится на ipgPn при соответствии сумме лимита.

── Этап 2 (O2 / LdM) — помесячные планы ───────────────────
  4. Создать ipgUtPlGr
  5. На каждого агента: ipgUtPl → привязка к группе
       (смена одного плана = новая группа + старые UtPl + один новый)
  6. impIpgLoadMonf ↔ ipgUtPl (+ путь); загрузка файла; повторить по агентам
```

«Утверждённая / одобренная» годовая ИП **не особый тип файла**: обычная `ipg`; в цепи — **первая по календарю актуальности**. Покрытие года — даты на членстве (`ipgChRl_2606.ipgcrvStr` / `ipgcrvEnd`); вести **сразу** при работе с цепью.

Этап 2 **не влияет** на этап 1.

## 5. Сверка структуры (ПТСФ) — §3.1.5

**ПТСФ** = выборка из `ags.impIpg` только строк-разделов (не листьев-строек).

### 5.1 Критерий авто-match → определённый `stiKey`

В выбранной для работы сети (`ipg.ipgStRlSh` / CardStrip при подготовке схемы):

1. **Имя:** сырой текст ∈ пул `stIpgNm` **или** нормализованное совпадение с любым именем пула.  
2. **Путь:** путь из Excel совпадает **хотя бы с одним** путём к узлу в этой `stNet` (DAG: OR по путям; на эталоне прода max 2 пути, ≥3 не встречалось).

Омонимы в домене есть (`Транспорт` sti 25 и 26; `АСУ ТП` 34 и 239) — **имя без пути не даёт «+»**.

### 5.2 Нормализация (только для поиска)

trim; NBSP→пробел; схлопывание пробелов; регистр не различать; кавычки `«»`/`"` к одному виду; срез префикса нумерации `2.1.1.` в начале.  
В `stIpgNm` хранить **сырой** пул (опечатки, двойные пробелы) — ловля повторов из правок Excel.

### 5.3 Статусы нижней таблицы (неопределённость)

| Состояние | Действие оператора |
|-----------|-------------------|
| Имя ни с чем не стыкуется | кандидат нового пункта / create |
| Найден `stiKey`, сырой текст не в пуле | кнопка «добавить имя» в `stIpgNm` |
| Имя есть, путь не сходится | правка схемы / пути / ручной map |
| Омоним (несколько `stiKey`), путь не выбрал | **ручной выбор `stiKey`** в ПТСФ |

### 5.4 «+» в FemsqTreeList

Только когда по строке ПТСФ **всё закрыто** и возвращаться не нужно: есть `stiKey`, при необходимости сырое имя уже в пуле (или совпало), путь согласован. Иначе строка остаётся внизу.

### 5.5 UI Structure

- Выбор схемы: CardStrip; дерево: FemsqTreeList с «+» на закрытых узлах.  
- Выбор файла Excel для сверки.  
- Низ: **набор вкладок**; сейчас одна вкладка — «не сопоставлено»; наращивание (работа с выбранным узлом и т.п.) — позже.  
- Перед replace/truncate staging — **предупреждение**.

### 5.6 Листья в `impIpg`

У строки-стройки: **стабильный id раздела-родителя в staging** (не доменный `stiKey`) + **номер строки** Excel. При загрузке лист наследует `stiKey` закрытого родителя-раздела.

### 5.7 DoD сверки / gate загрузки пунктов

ПТСФ без открытых строк → можно грузить пункты на экране **ipg** (в контексте `impIpgLoad`).  
Иначе — отказ и возврат на Structure.  
Каждый загружаемый `ipgPn` обязан получить `stiKey` (`ipgStPn`); пунктов «вне структуры» в Excel нет → отсутствие `stiKey` = **ERROR**, не warn. (Эталон ИП 34 с 2 пунктами без `ipgStPn` — недопустимое конечное состояние для FEMSQ.)

Маппинг колонок Excel→`ipgPn` — UI на экране **ipg**.  
Путь к файлу — строка в load/Monf; доступность файла — ответственность оператора.

## 6. Помесячные планы (этап 2) — решения, влияющие на O2/LdM

- **`Monf → ipgUtPl`** достаточно для загрузки файла (как Access); **`ipgUtPlGr` на файле не вешать** — группа для `_2606` только на членстве цепи.  
- Комбо выбора плана (к группе и к Monf): только `ipgUtPl` с **`iuplIpg = текущая ipg`**.  
- Один `ipgUtPl` может входить в несколько групп (сценарий «новая группа + старые планы + один новый»).
