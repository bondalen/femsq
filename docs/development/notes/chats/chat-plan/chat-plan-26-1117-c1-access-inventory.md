> **Зачем.** Нужна **актуальная карта** Access по освоению (P2): что есть в рабочем файле и к каким этапам это относится. Решение «переносить или нет» по каждому артефакту **не** цель C1 — оно появляется в ходе разработки C2–C5. Январская выгрузка VBA устарела (docs-sync **Р-43**, **Д11**); C1 её заменяет каталогом + UTF-8 VBA.

## 0. Цель

1. Актуальная выгрузка VBA и каталог объектов рабочего файла Access (один файл) → в репозитории.
2. **Карта-индекс** групп объектов → этапы P2 / «не P2» / смежно ([registry.md](../../../../project/proposals/vba-analysis/c1-inventory/registry.md)) — для навигации в C2–C5.
3. Зафиксировать принцип: migrate-решения и ответы на вопросы из [03-processes.md](../../domain/mastering/03-processes.md) — **по ходу** разработки затронутого функционала, не заранее.
4. Предложить порядок C2/C3 (R1.1 / R1.2) на уровне дорожной карты (без полного разбора артефактов).

**Критерий закрытия C1:** каталог + VBA в репо; карта групп; `03-processes` ссылается на актуальный источник; порядок R1.1/R1.2 записан в дорожной карте. **Не требуется** решение «перенести/нет» по каждой строке.

**Не входит:** разработка экранов и загрузчиков (C2/C3); полный семантический разбор всех форм/запросов; доработка Access.

## 3. Формат карты (registry.md)

Группы (G1–G20): объект/маска · вид · этап P2 (ориентир) · кратко назначение · трек при касании.

Колонок «частота» и «решение перенести» **нет** — они заполнялись бы бесконечно и устаревали бы до разработки. При работе над фичей решение фиксируется в плане этой фичи.

## 4. Требования к модулю-каталогу (1.1)

- Выводит в UTF-8 (`ADODB.Stream`, как в образцах) по одному файлу на вид объектов из [CAPTURE §4.2](../../../../project/proposals/vba-analysis/MS-ACCESS-OBJECTS-CAPTURE.md): формы (все, включая без кода: `RecordSource`, подформы `SourceObject`, кнопки и `OnClick`, `DateModified`), отчёты (`RecordSource`, подотчёты, `DateModified`), запросы (тип, SQL, `DateModified`), макросы, связанные таблицы (`Connect` → объект SQL Server).
- Формы и отчёты открывает в режиме конструктора скрыто и закрывает **без сохранения**; объекты не меняет.
- Запускается на **копии** рабочего файла; ошибки по отдельному объекту пишет в файл и продолжает.
- Одна процедура верхнего уровня с параметром «каталог вывода»; при неоднозначности имён (как с `DumpTableDef_Extended`) — вызов с именем модуля.
