## 0. Цель

Довести экран D до операционного паритета Access `CnInvPmtUpl>File_f` **после** успешной воронки: живые нижние вкладки, вкладка «счета, сумма», ручной разбор СФ (в т.ч. InvNot left>0 и TwoLoad), связь с КСДСФ/`g_p`, UX лаунчера.

**Критерий закрытия:** оператор на DEV (пакет вроде pm=59) после flLoad видит N на вкладках, разбирает хвост СФ/строек из UI (не только HTML-лог), видит Sum_t и статус связи `g_p`; UAT чеклист vs [02-11](../../UI/02-11_cn-inv-pmt-upl-access.md) пройден.

## 2.1. Правило трёх компонентов

После **1.7** экран не собирает обход сам и не импортирует renderer.

| Компонент | Где | Кто вызывает |
|-----------|-----|----------------|
| `FemsqTree` | feQuLib | только `FemsqWalkTree`, когда у JSON нет `view` или `outline` |
| `FemsqTreeList` | feQuLib | только `FemsqWalkTree`, когда `"view": "list"` |
| `FemsqWalkTree` | feQuLib | любой обход: один `rootId` или лес `root.queryId` |

**Когда list.** В строке несколько полей, которые сравнивают, не открывая карточку: ключ, номер, дата, сумма. Сюда входят вкладка «стройки новые», канон долга и `inv-dbt-slots`.

**Когда outline.** Дерево глубокое, уровни — разные таблицы, `detail` = «*». Карточка полей остаётся в `FemsqTree`. Сюда входят КСДСФ (`ksdsf-inv-num`, суммы cid/dv), договоры и выбор договора.

Для list число дорожек задаёт `columnSets`: оно равно длине самой широкой ветви. Подписи полей у папки — в строке папки (дорожки 1…N), отдельной caption-строки нет (**1.7.3.1** ✅). Метка ветви — любая строка (`node.level`). Плоский `columns` без `columnSets` — одна липкая шапка. При **`columnSets`** после **1.7.7.2**: липкая шапка **корневого** комплекта (`root.level`) вместо пустого ruler; вложенные уровни по-прежнему через строку folder.

**Читаемость list (**1.7.3.2** ✅ + **1.7.7** + **1.7.8**).** Две зоны nav|data; H-scroll; folder-токены. **1.7.7:** auto-expand+load; компактный empty; корневая шапка. **1.7.8:** one-line на **узлах** (fix scoped CSS: `__line` flex в `FemsqTreeListNode`).

## 2.2. Вкладка «Долг» — цепь портфелей (лист **1.7.6**)

**Контекст:** после split на 11897 график по календарным датам всех `DbtValue` врёт (18 000 вместо 36 000): смешивает портфельный **901** (2×18 000) и внепортфельный **910** (36 000 на #0). feQuLib **0.1.15** уже мапит `area`/`stack`/`step`.

### Решения (зафиксировано 2026-09-27; цепь уточнена **2026-09-28** → **1.7.6.7**)

| # | Решение |
|---|---------|
| **Цепь** | Не сущность БД. Участие = ≥1 Value на upl ∈ `yr_upl_p` данного `yr`. Группировка по **календарному году** портфеля (`year(base.uplStatusOnDate)+1`). `P(Y)` — портфели года Y с участием. **Число цепей** `N = ∏_{Y:\|P(Y)\|≥1} \|P(Y)\|` (годы с одним портфелем не умножают; пропуски лет — нет). Каждая цепь = выбор ровно одного `yr` из каждого `P(Y)`. **`N=0`** (нет участия ни в одном yr) → комбо **скрыто**, на графике **только** red «вне портфеля». Своды вне pf **не** множат `N`. Именование: якорь = ранний год с \|P\|>1 (иначе minY-1) + `{YYYY}-{k} {yr_variant}` + токены поздних ветвей `{YYYY}-{k}` + `, {minY}-{maxY}`. Сортировка по кортежу индексов. |
| **Точки области** | Только upl **выбранной цепи**, по порядку дат/`upl_key`. На каждом upl — стопка долей (слоты с Value на этом upl); внутри слота — проср. + текущ. |
