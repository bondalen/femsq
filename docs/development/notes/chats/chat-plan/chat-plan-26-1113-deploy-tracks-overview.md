## 1. Бизнес-обстановка (2026-11-13)

### СУДЗ

- Текущий квартальный цикл (до этапа «файл Excel для рассылки специалистам») выполнен на **DEV**.
- Предпочтительно **завершить этот цикл на DEV** (возврат комментариев → отчёт вышестоящему подразделению), чтобы не нести риски cutover и записи на prod посреди цикла.
- Реалистичный горизонт **продового** квартального цикла контура B — **QIV-26**, не текущий квартал.
- План 1019 и gate QIII на DEV **закрыты**; ★ **0918 / 1.1.2** (M6 cutover) ещё не GO. Код СУДЗ в монолитном JAR неизбежен при любой выкладке приложения, но **присутствие кода ≠ cutover ≠ приёмка 1.3.***.

### Освоение лимитов (`_2606` vs `_2605`)

Ежедневный бизнес сейчас на **`_2605`** + MS Access / VBA. Цикл:

| # | Этап | `_2606` сейчас |
|---|------|----------------|
| 1 | Внесение ИП и помесячных планов | **Не покрыт** (только чтение плана) |
| 2 | Обновление факта (отчёты агента и др.) | **Не покрыт** как ввод; `factDoc`/`factDocCost` — слой для расчёта |
| 3 | Расчёт освоения | **Движок есть** (`spMstrg_2606`, RS1–RS7); на DEV факт ≈ `_2605`, план/проценты **намеренно другие** (LmMn@212 + `ipgChRl_2606` vs `iuplpM*` + legacy gr 3/4/6) |
| 4 | Подготовка отчётов | **Клиенты не переключены** (`17.5` открыт; Access/Jasper → `_2605` / `*_2408_ResultSet*`) |

Замена `_2605` в процессе **не насущна**. Даже п. 3 («всего» / stCost 212) на prod-данных Access не готов: нужны согласованные данные цепи/плана для `_2606`, не только DDL.

### Общий вывод

Ни `_2606`, ни СУДЗ в текущем виде **не являются срочной бизнес-необходимостью** для замены ежедневного контура.  
Выкладка `_2606` на prod — прежде всего **проверка SQL-артефактов на SQL Server 2012**.  
СУДЗ на prod — подготовка к **QIV-26**, не к завершению текущего квартала.

## 2. Принятое решение по развёртыванию

| # | Решение |
|---|---------|
| R1 | **Не** big-bang: `_2606` + полный cutover СУДЗ + переключение клиентов освоения в одном GO |
| R2 | Треки **независимы** по схеме и календарю; СУДЗ **не** стоит в очереди за полной заменой `_2605` (п. 1–4) |
| R3 | **`_2606`:** допустим **минимальный** SQL-тест на prod (объекты рядом с `_2605`, VERIFY, без **17.5**) |
| R4 | **СУДЗ:** текущий квартал — **DEV**; прод-окно ориентир **QIV-26** после готовности **1.1.2** |
| R5 | Выкладка JAR с кодом СУДЗ (если понадобится раньше cutover) — только при правиле **СУДЗ dormant** (оператор не ведёт контур B на FEMSQ до окна H) |
| R6 | Полная замена цикла освоения 1–4 — **отдельный трек** (новый план чата при старте) |

### Отклонённые / отложенные варианты

- Параллельный релиз «оба пакета + JAR» **до** готовности cutover (**1.1.2**).
- Переключение Access/FEMSQ на `_2606` (**17.5**) до покрытия данных/клиентов под ежедневный «всего».
- Cutover СУДЗ ради завершения **текущего** квартального цикла.

## 3. Треки (кратко)

```text
A  _2606 SQL-тест на prod (артефакты 2012)     → план 0604 v2
B  СУДЗ: DEV до конца цикла → prod к QIV-26    → план 0918
C  Замена _2605 в БП освоения п.1–4            → новый план (позже)
```

**A — ближайшие шаги в 0604:** smoke после паузы → **21.5** (`05c` в порядок MSSQL2012 / db-upgrade) → **19.7** / **17.2.2b** флешка → при окне: apply SQL на prod + VERIFY (**без** 17.5).

**B — фокус 0918:** завершение текущего цикла на DEV; ★ **1.1.2** без сдвига текущего квартала на FishEye; выкладка **1.2** / приёмка **1.3** — к горизонту QIV-26.

**C — задел (не стартован):** ввод ИП/планов и/или мост к данным Access (gr 3/4/6, `iuplpM*` vs LmMn); проводка клиентов; приёмка «всего» на живых данных. Пока достаточно этого абзаца.
