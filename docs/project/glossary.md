## Назначение

Единый реестр терминов предметной области и проекта. Новые термины добавляются **в алфавитном порядке** (по заголовку на русском языке). При изменении определения обновляйте поле **Последнее обновление** у соответствующей статьи и дату файла.

В реестре четыре **типа статей** (указывается в первой строке тела, если не очевиден из названия):

| Тип | Содержание | Обязательные блоки |
|-----|------------|--------------------|
| **Сущность** | доменный объект, Excel-признак, таблица | определение; **Не путать с**; **См. также** |
| **Явление** | повторяющийся бизнес-паттерн | определение; **Где встречается** (таблица типов документов); **Не путать с** |
| **Ограничение модели** | инвариант БД / UX / CHECK | зерно ключа; следствие для явлений |
| **Контур расчёта** | куда факт попадает в отчёте освоения | связь с `typeGr` / колонками PercentBrn |

Длинная фактура прогонов, матрицы и доказательства — в доменных конспектах (для ОА: [`domain/ra/01-oa-signs-and-presentations.md`](../development/notes/domain/ra/01-oa-signs-and-presentations.md)), не в статьях глоссария.

**Связанные документы:** `docs/project-documentation-rules.md`, `docs/development/notes/sql/26-0604/docs/03-design-decisions.md`

## А

### Агентский эталон (agency-golden)

Тестовая стройка (или пара строек) для приёмки **агентской** схемы (`ipgpSh = 2`): динамика `ag_presented` / `ag_accepted`, помесячный и накопленный план (`ag_Pl` / `ag_PlAccum`) при смене ИП **6 / 8 / 11**, декомпозиция UtPl по stCost.

**Принято (Решение 21, цепь 5):** `@ipgStKey = 4`, `cstAgPn` **849** (`051-2000973`) и **1862** (`051-2000860`) — две agency-стройки в одном узле структуры.

**Не использовать для agency-тестов:** invest-golden **2102** (только `ipgpSh = 1`, факт освоения ≈ 0).

**См. также:** инвестиционный эталон, `13-plan-stcost-monthly-acceptance.md` §17–18.

**Последнее обновление статьи:** 2026-06-30.

### Аренда земли (РАЛП)

Вид факта освоения: отчёты по аренде земельных участков (`ralp`, `ralpRa`, `ralpRaAu`), элемент структуры затрат **150**. Загружается **ревизией** `af_type = 3` (`RalpAuditFileProcessor`). На проде выполняется в FEMSQ (JAR 156). Этап **БП P2 2.3**.

Несколько циклов рассмотрения одного отчёта аренды хранятся в **`ralpRaAu`** (образец **многократного представления**). Строки «ОА Аренда» в своде ОА — тот же контур факта, в type=5 **не** загружаются (whitelist).

**См. также:** многократное представление, ОА Аренда, ревизия, [business-processes.md](business-processes.md), план [0707](../development/notes/chats/chat-plan/chat-plan-26-0707-ralp-reconcile.md), [domain/ra/01](../development/notes/domain/ra/01-oa-signs-and-presentations.md).

**Последнее обновление статьи:** 2026-11-19.

## В

### Внелимитная стройка (OUT_GROUP)

Стройка (`cstAgPn`) цепи, **не** входящая в IN_GROUP выбранного узла `@ipgStKey` (нет привязки `ipgStPn` к поддереву узла), но попадающая в отчёт, если:

1. её **тип по 5-й литере** кода САК разрешён в `ags.stIpgOutLimPn` для `@ipgStKey`;
2. стройка ∈ **`chainActive`** (7 источников, как `fnIpgChRsltCst` — Решение 16, доп. 2026-06-29).

План и лимит из `ipgPn` могут отсутствовать; **факт** (RA, АВ и др.) отображается в RS по правилам `fn2`.

**Активность:** см. п. 2; отдельный предикат `lim>0` / `accepted>0` в TVF **не** применяется.

**Не путать с:** **неплановыми капзатратами (`np_`)** — OUT_GROUP задаёт **отбор строек** по разделу `stIpg`; `np_` — **раскладка капфакта** по схемам, когда у стройки нет пункта `ipgPn` на данной ИПГ (может быть и у стройки IN_GROUP).

**См. также:** универсум строек отчёта, тип стройки по коду САК, раздел структуры ИПГ, неплановые капзатраты.

**Последнее обновление статьи:** 2026-06-29.

## Г

### Группа планов (`ipgUtPlGr`)

Набор планов агентов (`ipgUtPlGrP`, `ipgUtPlP`), привязанный к инвестпрограмме через `ipgChRl_2606.ipgcrvUtPlGr` (до этапа 21.1: `ipgChRlV`). Определяет, какие строки уточнённого плана участвуют в расчёте освоения для данной ИП в цепи.

**Dev-fixture (цепь 5):** тестовые группы **18 / 19 / 20** (`TEST_CH5_IPG6/8/11`); prod-подобные группы **3 / 4 / 6** **не изменять** в fixture (Решение 21).

**Последнее обновление статьи:** 2026-06-30.

### Группа платежей одного срока (выгрузка платежей)

Узел традиционной раскладки `export_*`: набор **платёжных документов** (белых строк с «№ докум.»), закрытый одной **жёлтой** итоговой строкой уровня outline **3**. Срок оплаты — атрибут группы; два жёлтых итога с одинаковым сроком внутри одной **группы стройки** — **две** разные группы (пример: два вхождения 28.02.2026 у СФ `0620CR000478`).

В промежуточную таблицу жёлтая строка **не** пишется (Access и FEMSQ после фильтра «№ докум.»). На белых строках staging — суррогат `ciputDueKey` и порядковый `ciputDueGrp` (1…n внутри пакета+СФ+CAC+срок). В домене при InsPm — `ags.cn_inv_pm.cn_inv_pm_due_grp` (nullable; старые пакеты без перезаливки — `NULL`).

**Не путать с:** счётом-фактурой файла (несколько групп срока принадлежат одному СФ); **группой стройки**.

**См. также:** группа стройки (выгрузка платежей), традиционная раскладка `export_*`, [`export-row-tree-structure.md`](proposals/vba-analysis/26-0813_CnInvPmtUpl_/export-row-tree-structure.md).

**Последнее обновление статьи:** 2026-10-03.

### Группа стройки (выгрузка платежей)

Сплошной отрезок белых строк одного кода стройки («Код стройки» / `ciputCAC`) внутри одного **счёта-фактуры файла**. Собственной итоговой строки в Excel нет — узел собирается из документов уровня outline 4. На эталонном файле пакета 59 таких отрезков 5 648, все непрерывны. Staging-ключ отрезка — `ciputCacSpanKey`.

Ниже группы стройки лежат одна или несколько **групп платежей одного срока**.

**Не путать с:** стройкой предметной области `cstAgPn` / полем `constract_code` на `cn_inv_pm` (это уже принятый платёж); внелимитной стройкой отчёта ИПГ.

**См. также:** группа платежей одного срока, счёт-фактура файла, [`export-row-tree-structure.md`](proposals/vba-analysis/26-0813_CnInvPmtUpl_/export-row-tree-structure.md).

## И

### Изменение к отчёту агента (`ОА изм` / `ra_change`)

**Тип статьи:** сущность.

Строка Excel с признаком **«ОА изм»** и соответствующая запись `ags.ra_change` (суммы — `ags.ra_change_summ`). Это **не** отдельный `ra_type`: изменение ссылается на базовый `ags.ra`; отнесение к капитальным или прочим — по `ra.ra_type` базы (`ОА` vs `ОА, прочие`) после resolve по периоду и № базы.

Отдельного Excel-признака «изм. к прочим» нет. В текущих сводах изм. к «ОА, прочие» почти не встречаются; в истории БД — единичные случаи (см. конспект).

**Где встречается многократное представление:** да — несколько строк Excel с одним № изменения к одной базе в одном периоде (история рассмотрения). Текущий UX `ЗаПериодЗаОтчётОдинНомер` это запрещает → блокер apply type=5 (R1.0 §1.4).

**Не путать с:** собственно отчётом **ОА** / **ОА, прочие**; разными номерами изменений (Изм. 1 и Изм. 2) к одной базе.

**См. также:** многократное представление, уникальность изменения за период, отчёт агента (ОА), ОА прочие, прочие затраты (`oh_`), [domain/ra/01](../development/notes/domain/ra/01-oa-signs-and-presentations.md).

**Последнее обновление статьи:** 2026-11-19.

Версия инвестиционной программы в рамках цепи (`ipgCh`). Имеет срок актуальности в цепи: `ipgcrvStr` … `ipgcrvEnd` в таблице `ipgChRl_2606` (до 21.1: `ipgChRlV`). На конкретную дату расчёта актуальна **не более одной** ИП цепи.

### Инвестиционный эталон (invest-golden)

Тестовая стройка для приёмки **инвестиционной** схемы, календаря RS1 (17 дат), фильтра `stIpg` на листе дерева.

**Принято (Решение 21, цепь 5):** `@ipgStKey = 42` (или **61**), `cstAgPn = 2102`; колонки `iv_*` / `ia_*`; UtPl fixture в группах **18–20**.

**Не путать с:** agency-golden (факт и план по `ag_*`).

**Последнее обновление статьи:** 2026-06-30.

### Связь цепь–инвестпрограмма (`ipgChRl_2606`)

Таблица сроков актуальности ИП в цепи (замена legacy `ipgChRl` по Дефекту Б). Хранит `ipgcrvStr`, `ipgcrvUtPlGr`; `ipgcrvEnd` — вычисляемый столбец (`fnIpgChRlEnd_2606`).

| Объект | Legacy (prod) | Стек `_2606` (целевое имя) |
|--------|---------------|----------------------------|
| Связь цепь↔ИП | `ipgChRl` | **`ipgChRl_2606`** |

Mastering и приёмка UtPl (`07n`/`07o`) читают **`ipgChRl_2606`**. До этапа **21.2** PercentBrn plan-JOIN ещё может ссылаться на legacy `ipgChRl` — дефект, устраняется патчем `05b`.

## К

### Календарь контрольных дат RS1 (`fnIpgChDats_2606`, `dateRslt`)

Упорядоченный набор дат среза для **полного рекордсета RS1** (графики Java/FEMSQ, 01.01–31.12 расчётного года). В стеке `_2606` **канонический** источник — `ags.fnIpgChDats_2606(@ipgCh)` (до 21.1: `fnIpgChDatsV`):

| Компонент | Содержание |
|-----------|------------|
| Начало года | **01.01** (`dAll`) |
| Месяцы | 12 × конец месяца (`EOMONTH`) |
| Смена ИПГ | `ipgcrvStr` / `ipgcrvEnd` из `ipgChRl_2606` |

**Цепь 5, 2022:** **17** дат. PercentBrn / RS1 **обязаны** выдавать те же `dateRslt`, что `fnIpgChDats_2606` (Решение 17).

**Legacy `_2605`:** календарь `@dt` в PercentBrn даёт **16** дат (без 01.01); костыль `mNum=0` в plan-JOIN — **дефект**, не целевая модель.

**Не путать с:** `@MounthEndDate` (фильтр RS4–RS7 для Access); помесячной матрицей fn2 (`mNum` 1…12).

**См. также:** начальная точка графика, накопленный план. `06-sp-recordsets-and-acceptance.md`, `03-design-decisions.md` §17.

**Последнее обновление статьи:** 2026-06-30.

## М

### Многократное представление (рассмотрение в несколько подходов)

**Тип статьи:** явление.

Один логический документ проходит несколько циклов рассмотрения (поступление → служебная записка / возврат → повторная подача) с сохранением **истории** каждого подхода. В Excel это несколько строк с одним бизнес-номером документа; в домене — либо несколько дочерних записей, либо (ошибочно) попытка схлопнуть в одну строку с уникальным ключом.

**Где встречается**

| Тип документа | Носитель | Поддержка истории | Примечание |
|---------------|----------|-------------------|------------|
| Изменение к ОА (`ОА изм`) | `ags.ra_change` | **нет** (одна строка на период+база+№ изм.) | конфликт с UX; бизнес историю требует |
| Изменение к «ОА, прочие» | `ags.ra_change` | та же модель | редко в данных; тот же UX |
| Аренда земли (РАЛП) | `ralpRa` + `ralpRaAu` | **да** | образец целевого поведения |
| Собственно ОА / ОА прочие | `ags.ra` | одна строка отчёта на ключ периода+№ | вне блокера RC |
| «ОА Аренда» в своде ОА | контур РАЛП | через type=3 | в type=5 не загружается |

**Не путать с:** несколькими **разными** номерами изменений к одной базе; повторным прогоном ревизии (идемпотентность staging/apply); двумя представлениями плана UtPl (широкие колонки vs `ipgUtPlPnLmMn`).

**См. также:** уникальность изменения за период, изменение к отчёту агента, аренда земли (РАЛП), [domain/ra/01](../development/notes/domain/ra/01-oa-signs-and-presentations.md).

**Последнее обновление статьи:** 2026-11-19.

## Н

### Накопленный план

Сумма помесячных плановых показателей UtPl с начала расчётного года до контрольной даты (`dAll` / `@MounthEndDate`). В стеке `_2606` отображается в полях `smmTtl`, `agSmmTtl` и аналогах PercentBrn (`ag_PlAccum`).

На дате окончания периода ИП (`ipgcrvEnd`) накопленный план равен cum UtPl на эту дату и **не обязан** совпадать с годовым лимитом, если ИП снята раньше 31.12.

### Начальная точка графика (01.01)

Контрольная дата **первого января** расчётного года в календаре RS1. Семантика для активной ИПГ на графике освоения:

| Показатель | Ожидание на 01.01 |
|------------|-------------------|
| `ag_Pl`, `ag_PlAccum` | **0** (годовой план ещё не начался) |
| `ag_presented`, `ag_accepted`, … | **0** |
| `ag_lim` | лимит ИПГ на год |
| `ag_restOfLimit` | **≈ лимит** («не освоено и не должно быть освоено») |

Входит в `fnIpgChDats_2606` и mastering; **должна** присутствовать в RS1 после реализации Решения 17. В legacy PercentBrn отсутствовала в `@dt` — добавлялась костылём `mNum=0`.

**Последнее обновление статьи:** 2026-06-30.

### Неплановые капзатраты (`np_`)

**Капитальные** затраты (`typeGr = '1. ОА и Изм.'`) с фактом освоения, но **без пункта `ipgPn`** на данной ИПГ (или без привязки инвестора к цепи). В `fn2` получают `typeGrTtl = '2.2. Агентская, неплан'`, `lim = NULL`, `iShKey = NULL`.

В `PercentBrn` / RS суммы попадают в колонки с префиксом **`np_`** (`np_accepted`, `np_acceptedTtl`, …), **не** в `ag_*`. На **% освоения лимита** (`ag_LimPercent`, `ag_percentDev`) **не влияют**.

Типичные пути в `fn2_2606`: CTE **`extraBase`** (стройка не в `ipgPn` цепи, инвестор в ИПГ) и **`masExtraBase`** (стройка в mastering, но на этой `ipgKey` нет `ipgPn`).

**Не путать с:** внелимитной стройкой (OUT_GROUP) — фильтр по `stIpg`; с **прочими затратами (`oh_`)** — отдельный некапитальный контур.

**См. также:** пункт инвестпрограммы, `09-scheme-cascade-mastering.md` (слой C).

**Последнее обновление статьи:** 2026-06-29.

### Нетрадиционная раскладка `export_*` (QII)

Выгрузка платежей БУиРГ с другим набором колонок (казус счетов **767501/767502** среза **26-0817**): якорь «№ докум.» не в колонке U; добавлены «Опер.сегмент», «Вид контрагента», сальдо начальное и обороты; **нет** «Срок оплаты», «БазДата», «Сумма документа». Документ на уровне outline **7**; ближайший итог (уровень **6**) закрывает стройку договора и может содержать много номеров СФ.

Импортёр FEMSQ читает колонки по ключевым словам заголовка ([`export_offset-map.md`](proposals/vba-analysis/26-0813_CnInvPmtUpl_/export_offset-map.md)). Файлы `*.remapped_canon.XLSX` повторяют заголовки традиционной книги, но срок оплаты пуст и дерево outline снято.

**См. также:** традиционная раскладка `export_*`, группа платежей одного срока, [`export-row-tree-structure.md`](proposals/vba-analysis/26-0813_CnInvPmtUpl_/export-row-tree-structure.md) §3.2.

**Последнее обновление статьи:** 2026-10-03.

### Номер платёжного документа («№ докум.», `cn_inv_doc_kod`)

Код документа в колонке «№ докум.» выгрузки и в каталоге `ags.cn_inv_doc`. На экране КСДСФ платежей в Excel-кандидате показывается как **doc** (`ciputCnInvDocCode`).

**Не уникален** ни глобально, ни как пара «номер + дата документа»: один код встречается в разных годах, на разных СФ и договорах; внутри одного пакета одна пара номер+дата может повторяться с разными сроками оплаты. История часто показывает **перенос** уже известного документа на другой СФ, а не второй документ с тем же кодом.

**Не путать с:** номером СФ («Присвоение» / `invNum`); колонкой «Ссылка» (`ciputLink`).

**См. также:** [`export-row-tree-structure.md`](proposals/vba-analysis/26-0813_CnInvPmtUpl_/export-row-tree-structure.md) §6.

**Последнее обновление статьи:** 2026-10-03.

## О

### ОА Аренда (признак в своде ОА)

**Тип статьи:** сущность (исключение отбора).

### Подозрительный номер СФ

Класс «пустых» номеров присвоения в выгрузке и в `invNum`: пусто, `б/н` / `Б/н` / `БН`, `Б/С`, `-`, `*`. Короткие числа (`92`, `14`) к классу **не** относятся.

Правило Access «кредитор + договор + номер» даёт один СФ на договор; в истории так и хранится (несколько строек и сроков внутри одного «б/н»). Разные стройка или срок сами по себе **не** доказывают новый СФ (у настоящего номера разные сроки — внутренние **группы платежей одного срока**). Для идентификации — фильтр поиска среди существующих СФ с таким номером на договоре; при неоднозначности — очередь КСДСФ.

**См. также:** счёт-фактура файла, группа платежей одного срока, [`export-row-tree-structure.md`](proposals/vba-analysis/26-0813_CnInvPmtUpl_/export-row-tree-structure.md) §5.

### Помесячный план по элементу stCost (`ipgUtPlPnLmMn`)

Нормализованное хранилище **планового (планируемого) освоения на месяц** по **пункту уточнённого плана** и **элементу структуры затрат**.

**Модель данных:** одна строка = комбинация `(iuplpmPlPn, iuplpmStCost, iuplpmMn)`; сумма в `iuplpmLim` (в миллионах руб., как в `ipgPnLim`). Хранится **только** при `iuplpmLim > 0` (**sparse**); отсутствие месяца = **нет строки**, не нулевая сумма.

**Ограничение целостности:** `CK_ipgUtPlPnLmMn_gt0` (`iuplpmLim > 0`); включается скриптом `09c` (Решение 15). Аналоги: `ipgUtPlPnLmQu`, `ipgUtPlPnLmYe`. Legacy `CK_*<>0` сняты в `09c`.

| Колонка | Смысл |
|---------|--------|
| `iuplpmPlPn` | FK → `ipgUtPlP.iuplpKey` |
| `iuplpmStCost` | Элемент структуры затрат (`stCost`) |
| `iuplpmMn` | Номер месяца (1…12) |
| `iuplpmLim` | Плановое освоение за месяц (**> 0**) |

**Использование в стеке _2606:** чтение через `ags.fnStCostUtPlPMn` → `fnStCostRsIpgPn_2606` → mastering / `spMstrg_2606`. Приёмка: скрипты `07m`/`07n`/`07o`, fixture `dev-chain5-utpl-stcost/`. Контроль: `SUM(iuplpmLim)` по **существующим** месяцам ≈ лимит `ipgPnLim` (или fallback `ipgpSmTtl` / `ipgpSmWrk` / …) для stCost **212 / 195 / 172 / 187**.

**Не путать с:** широкие месячные колонки `ipgUtPlP` (итог без stCost, legacy UI); `ipgUtPlPnCostIts` (устаревшая широкая таблица); нулевые строки «для заполнения сетки 12×4» в fixture (запрещено с 18.8.2, см. Решение 15).

**Последнее обновление статьи:** 2026-07-06.

## Ш

### Широкие месячные колонки `ipgUtPlP` (`iuplpM01`…`M12`)

Помесячное плановое освоение в **денормализованном** виде: по одной паре колонок на месяц (`iuplpMnn` — прирост за месяц, `iuplpMnnAccum` — накопленный итог с начала года). Хранятся на **заголовке** уточнённого плана (`ipgUtPlP`), без отдельной колонки `stCost`.

**Семантика уровня stCost:** колонки **не разбивают** план по 195/172/187; по смыслу соответствуют **суммарному плану уровня итога структуры затрат — stCost 212** («всего по объекту»), как `ipgpSmTtl` / `ipgPnLim@212`. Декомпозиция на подвиды — только в `ipgUtPlPnLmMn`. Сверка: К-12 сравнивает `SUM(iuplpmLim)` при `iuplpmStCost=212` с лимитом 212; К-13 — равенство 212 = 195+172+187 **в LmMn**, не в `iuplpM*`.

**Единицы:** миллионы рублей (как в `ipgUtPlPnLmMn`); в PercentBrn умножаются на `1 000 000`.

| Аспект | `_2605` / legacy PercentBrn | `_2606` (mastering) |
|--------|----------------------------|---------------------|
| Чтение `iuplpM*` | **да** — подзапросы gap/gip/gup | **нет** |
| Чтение `ipgUtPlPnLmMn` | косвенно / не для RS-колонок плана | **да** — `fnStCostUtPlPMn` → `fnStCostRsIpgPn_2606` |
| Sparse UtPl (Решение 15) | prod: часть строк с заполненными `M*`; dev fixture gr 18–20: часто **только LmMn** | отсутствие строки LmMn = план `0` |

**Связь с группой планов:** `ipgUtPlP.iuplpPl` → `ipgUtPlGrP` → `ipgUtPlGr`; активная группа на ИП в цепи — `ipgChRl_2606.ipgcrvUtPlGr`. У одного `ipgPn` может быть **несколько** строк `ipgUtPlP` (разные `iuplpPl` / группы); LmMn привязан к конкретному `iuplpKey`.

**Связь `iuplpSubAg` / og на заголовке:** историческая привязка к филиалу агента; после смены филиала в рамках одной ИП практическая ценность для отчёта снижена (вне scope расчёта плана в `_2606`).

**Диагностика 21.4.2:** при заполненном LmMn и пустых `iuplpM*` mastering и К-12 проходят, а `ag_Pl`/`iv_Pl` в PercentBrn — нет (до реализации Решения 22).

**См. также:** плановые показатели UtPl, помесячный план по stCost, `03-design-decisions.md` §22, `diag-21_4_2-plan-align-findings.md`.

**Последнее обновление статьи:** 2026-07-06.

### Фантомный уровень филиала (GROUPING SETS)

Артефакт legacy `GROUPING SETS` в PercentBrn: при отсутствии филиала у стройки создаётся уровень агрегации `(ogNm, branch, dateRslt)` с **`branch = 0`**, дублирующий уровень агента в **RS1**. В производных RS4–RS7 такие строки отфильтрованы (`cstAgPnCode='всего' AND branch=0`), в RS1 остаются.

## У

### Универсум строек отчёта (IN_GROUP ∪ OUT_GROUP)

Множество строек (`cstAgPn`), попадающих в `fn2_2606` / `spMstrg_2606` при заданном `@ipgStKey`:

| Компонент | Определение |
|-----------|-------------|
| **IN_GROUP** | стройки с привязкой `ipgStPn` к `@ipgStKey` или потомку (`fnStDownAll` + корень) |
| **OUT_GROUP** | стройки цепи **вне** IN_GROUP, разрешённые `stIpgOutLimPn` по типу (`fnCstAgPnTypeChar`) и **`chainActive`** (7 источников, как `fnIpgChRsltCst`) |

При `@ipgStKey = NULL` — вся цепь (без сужения). При листовых узлах без строк в `stIpgOutLimPn` (напр. 42, 61) — только IN_GROUP.

Фильтр универсума **не меняет** раскладку факта по схемам внутри стройки: капфакт без `ipgPn` → `np_*`, некапитальные → `oh_*` (см. отдельные статьи).

**См. также:** внелимитная стройка, раздел структуры ИПГ, неплановые капзатраты, прочие затраты в отчёте. Решение 16 в `03-design-decisions.md`.

**Последнее обновление статьи:** 2026-06-29.

### Уникальность изменения за период (`ЗаПериодЗаОтчётОдинНомер`)

**Тип статьи:** ограничение модели.

Уникальный индекс / UX на `ags.ra_change`: одно изменение с данным **номером** к данному **базовому отчёту** в данном **`ra_period`**. Зерно: `(ra_period, rac_ra, rac_num)` (в DDL колонки `rac_*` могут содержать кириллическую «с»).

**Следствие:** запрещает хранить **многократное представление** одного и того же № изменения. При apply type=5 несколько строк Excel с одним зерном → SQL Server **2601**, откат транзакции reconcile (наблюдение R1.0 DEV-гейт, 2026-11-19).

**Не путать с:** уникальностью собственно отчёта `ags.ra` по периоду+№; идемпотентностью повторного apply.

**См. также:** многократное представление, изменение к отчёту агента, [domain/ra/01](../development/notes/domain/ra/01-oa-signs-and-presentations.md).

**Последнее обновление статьи:** 2026-11-19.
