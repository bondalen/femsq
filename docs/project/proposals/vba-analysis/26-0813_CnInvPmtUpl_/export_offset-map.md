## FEMSQ (с 2026-09-21): колонки по ключевым словам

**Казус QII `export_*_26-0817`:** счета **767501/767502** пришли с другим набором колонок (якорь «№ докум.» @ col 18; добавлены «Опер.сегмент», «Вид контрагента», обороты/сальдо начальное; иначе порядок дат/ссылок). Фиксированный Offset (−20…+5) давал «якорь слишком близко к левому краю» → Tbl 0.

**Решение в коде** (`SudzPmtUplExcelToTblImporter`): якорь по-прежнему `Find("№ докум.")`; остальные поля — по нормализованным ключевым словам заголовка (стебли вроде «счет»+«гк», «сальдо»+«конечн»+«дт», пара «Агент»→ num/name). Отсутствующие в новом layout поля (срок оплаты, просрочки, баз.дата, сумма документа) → null.

**Staging QII (0922 1.13.7):** outline L7 = документ, L6 = отрезок стройки (`ciputCacSpanKey`); `ciputSfKey` с строки документа (кредитор+договор+присвоение); `dueKey`/`dueGrp` не пишутся. L6 не граница СФ.

Оригинал сырого layout на шаре: `*.raw_layout.XLSX`.

**Дерево строк и уровни outline** (жёлтый итог срока, группа стройки, сверка файлов периодов, предложения по staging-ключам): [`export-row-tree-structure.md`](./export-row-tree-structure.md).

## Отбор строки в Tbl (лист 1.9, 2026-10-19)

Таблица выше говорит, в какую колонку класть поле. В `CnInvPmtUplTbl` попадает не каждая строка листа.

| | Критерий строки | Цвет заливки |
|--|-----------------|--------------|
| Access `Form_CnInvPmtUpl_gt_File_f` | непустая ячейка якоря «№ докум.» | не читается |
| FEMSQ до 1.9.0 (`rowLooksLikePayment`) | «№ докум.» **или** БЕ **или** числовой счёт ГК | не читается |
| FEMSQ с 1.9.0 | непустой «№ докум.» | не читается |

До 1.9.0 жёлтые итоги СФ, контрагента, счёта и документа (пустой «№ докум.», заполнены БЕ или счёт ГК) попадали в Tbl. На `export_26-0130_767501` пакета pm=59 это было около 7 579 строк сверх ~15 942 платежей. Диагноз, очистка и приёмка: [план 0922 §2.4](../../../../development/notes/chats/chat-plan/chat-plan-26-0922-pmt-upl-ui-complete.md).

С 1.9.0 импортёр пишет в Tbl только строку с непустым «№ докум.» (`DraftRow.white` в `SudzPmtUplExcelToTblImporter`). Строка без номера может остаться в памяти как жёлтый итог outline и дать ключ срока; в `CnInvPmtUplTbl` она не вставляется.

Страховка 1.9.1 для уже залитых пакетов: InvNot, TwoLoad и `rebuildPmtUplSfDouble` требуют `ciputCnInvDocCode` не NULL и не из одних пробелов (`sqlPmtTblHasDocCode`).

Приёмка 1.9.4–1.9.6 на pm=59: Tbl 15 942, пустых «№ докум.» 0, очередь КСДСФ 18, строки-призрака с пустым номером нет. Якорь сальдо и счётчики 580/581 этой ветки записаны в `KSDSF_CONTEXTS` и здесь не повторяются.
