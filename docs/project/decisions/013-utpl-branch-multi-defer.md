# Решение 013: отложить параллельный сплит лимита UtPl по филиалам

**Дата:** 2026-11-27  
**Статус:** ✅ Принято  
**Участники:** Александр, Cursor AI  
**Задача (контекст):** **0081** (C2 / O2)  
**Проблема в реестре:** `P-2026-11-27-001`  
**Глоссарий:** [Разделение лимита пункта ИП по филиалам (multi)](../glossary.md)

---

## Проблема

В Excel помесячных планов (пример агент **051**, листы `двоящуры` / `branch`) лимит **одного** пункта ИП (`ipgPn` / код `051-2…`) иногда разносится на **>1 филиал одновременно**.  
В модели БД и стеке `_2606`:

- у `ipgPn` / `ipgUtPlP` / `ipgUtPlPnLmMn` **нет** оси филиала на суммах;
- Access LdM филиал **не читает**;
- `cstAgPnBranch` + `fnCstAgPnBranch` — **календарь** «один филиал на дату», не параллельный сплит лимита;
- **К-18c** — сохранение grand total при атрибуции отчёта, не multi-хранилище lim.

Реализация «загрузка multi + mastering» = отдельный большой этап (схема хранения, Excel/UI, `_2606`/`_2***`, приёмка).

---

## Рассмотренные варианты

1. **Реализовать multi в O2 сейчас** — раздувает scope без готовой модели; блокирует минимум UtPl.  
2. **Отложить; обход при подготовке файла** — один `ipgPn` / одна строка плана; суммы филиалов сводить к филиалу с **большей** суммой.  
3. **Частичная поддержка только в UI без `_2606`** — расхождение план↔отчёт; отвергнуто.

---

## Решение

Выбран **вариант 2**.

- В **O2 / текущей загрузке** помесячного плана multi-сплит **не** реализуется.  
- **Обход (принято):** при подготовке Excel лимиты по филиалам **суммируются к филиалу с большей суммой** (остальные филиалы в файле плана не держат долю того же пункта).  
- **Будущее:** отдельная задача «загрузка UtPl + `_2606`/`_2***`» на параллельный сплит; завести при появлении приоритета (бэклог за R1 / хвост D1.1).

---

## Последствия

| Контур | Следствие |
|--------|-----------|
| O2 / LdM | зерно без branch; филиал на отчёте — через `cstAgPnBranch` |
| `_2606` | без изменений под multi-lim |
| Данные 051 | ручная/предобработка как `двоящуры` → один филиал-носитель |

**См. также:** ADR 012 (деньги/оси — ортогонально); фантомный уровень филиала (GROUPING SETS, этап 20.6).
