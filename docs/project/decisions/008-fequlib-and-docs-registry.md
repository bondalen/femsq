Участники: Александр

Проблема

У Александра несколько проектов разной степени готовности. Два вида боли повторялись неоднократно раньше:

    Хороший грид/дерево-компонент (фильтрация, сортировка) нужен не только в FEMSQ — при повторной потребности дублировать/извлекать его из FEMSQ дорого и создаёт риск рассинхронизации.
    Система управления документацией проекта каждый раз изобретается заново; объём документации в начале кажется незначительным, но растёт нелинейно, и это стало причиной трудного старта нескольких прошлых проектов.

Рассмотренные варианты

1. Всё внутри FEMSQ (status quo)

    Плюсы: ноль накладных расходов сейчас.
    Минусы: при потребности в другом проекте — дублирование кода/схемы и ручная синхронизация.

2. Один общий репозиторий для UI-компонентов и системы документации

    Плюсы: одна точка обслуживания.
    Минусы: разные домены (Vue/Quasar-библиотека vs БД-сервис), разный жизненный цикл и стек — совмещение усложнит оба.

3. Два отдельных репозитория, с разной последовательностью запуска (выбрано)

    feQuLib — плюсы: чистая UI-библиотека на Quasar (App Extension/UI Kit — идиоматичный формат Quasar), не тянет БД-зависимости.
    Реестр документации — плюсы: независимый бэкенд-сервис на PostgreSQL, полезен сразу нескольким проектам без привязки к Vue/Quasar.

Решение

Выбран вариант 3, с разной готовностью к старту для каждой части:

Итоговая последовательность: **0059 → 0061 → 0060 → 0063 (projectize) → 0058 разблокирована**, а 0062 — отдельно, без спешки.

    0059 — фаза A `FemsqTable` внутри FEMSQ на реальных экранах (стройки, отчёты, аренда).
    0061 — MVP реестра документации на PostgreSQL **перед** `feQuLib`.
    0060 — вынос `FemsqTable` в `feQuLib`, регистрация в реестре как первый проект.
    0063 — projectize: GitHub, `docs/`, `.cursorrules`, отдельные окна Cursor (2026-07-28).
    0062 — перенос исторических данных FEMSQ в реестр — не срочно, не блокирует 0058.

### Дизайн: хост и библиотека (2026-07-29)

Чтобы грид был переиспользуемым и при этом выглядел «своим» в каждом приложении:

    Тема продукта (цвета, шрифты, light/dark, chrome) — **только у хоста** (в FEMSQ: Kimbie/VS Light, `--femsq-*`). fequlib не заводит копию темы продукта.
    Хроматика контрола грида (плотность, высоты строки/шапки/filter-row) — **у fequlib** через `--fequlib-table-*`; хост может переопределить.
    DevExpress-скрины в fequlib — эталон **плотности/паттернов**, не пиксель-копия и не палитра FEMSQ.
    Задача fequlib **0011** (registry); бриф: `docs/design/FemsqTable-visual-target.md` в fequlib; FEMSQ: `02-8`, план 26-0725 §8, `frontend-themes.md`.

### Дерево: renderer и walker (2026-08-18)

`FemsqTree` — только отрисовка. Обход JSON/рёбер — отдельный компонент (`RelationTree` → `FemsqWalkTree`). Не встраивать walker в `FemsqTree`. Подготовка контракта в FEMSQ (inject fetch) до выноса в lib. Подробно: [Решение 009](./009-femsq-walk-tree.md).
